# 前端工程

本目录为 Pack MES 管理与作业前端，使用React 18、TypeScript、Vite与MUI，迁入医疗套件的应用框架和通用管理交互。页面通过后端接口操作真实持久化业务事实，保留 Pack 制造内核。

完整环境、数据库、密码及后端启动步骤见[启动与配置手册](../docs/development/local-startup.md)。本机核对Node.js 22.21.0和npm 10.9.4，在本目录运行：

```sh
npm ci
npm run dev
```

开发地址为`http://127.0.0.1:5173`，Vite将`/api`代理到`http://127.0.0.1:8080`。先按[仓库启动入口](../README.md#本地开发与启动)在仓库根目录启动后端。默认关闭演示初始化；首次可使用固定内置系统管理员`admin / admin123`登录，无需额外初始化账号。重启不覆盖已修改的密码，已有账号继续使用原密码。内置管理员在用户管理中有明确标识，其角色和工厂授权由系统维护。登录页不预填或展示默认密码。

会话令牌保存在当前标签页的`sessionStorage`。刷新恢复登录时先请求`/api/me`核实会话与当前服务器授权，通过后恢复工作空间；失效则清除会话并返回登录。退出登录会清除本标签页令牌并撤销服务器会话。

`5173`占用会直接报错。可用`npm run dev -- --port 5174`调整前端端口；后端改端口时必须修改`vite.config.ts`中的`server.proxy`并重启Vite。当前没有`VITE_API_URL`配置，根目录`.env`的后端变量不会自动改变代理。不要把密码放入`VITE_`变量。

`npm ci`只在首次安装或锁文件变化时执行。日常用`npm run dev`启动，`Ctrl+C`停止。`npm run build`输出到`dist/`，随后可用`npm run preview -- --port 4173 --strictPort`在本机预览；当前Vite预览继承`/api`代理，后端仍需运行。JAR不包含前端；正式静态托管还须配置`/api`反向代理。

```sh
npm test
npm run build
```

自动检查覆盖会话恢复、权限导航、请求丢失回执时沿用原ID和不可变载荷、业务拒绝及消息冲突状态。构建检查TypeScript及生产打包。本轮前端15项、后端38项测试及实际运行验证见[管理与作业界面迁移记录](../docs/development/management-ui-migration-2026-10-23.md)；这些检查不替代真实现场验收。锁文件固定依赖；`nanoid`和`postcss`的覆盖版本用于固定可复现依赖，与本轮离线缓存匹配。

工作空间包含模块导航、多页签和工作首页；系统管理提供用户、角色权限、组织、菜单、设置及日志；主数据提供物料与版本、派生产品、工序、路线与版本、设备、工厂资源、受控文档/SOP、字典和原因代码。生产页面提供制造版本、工单、生产对象、扫码作业、质量返修、接口消息及全程追溯。原始检测结果、当前证据有效性、生产完成与质量放行分别显示，设备和外部MES接入使用明确来源的专用账号。

当前身份仅能选择服务端授权的工厂；前端按钮限制不代替服务端鉴权。断连时不创建离线放行，结果不确定的命令保留原作用域、载荷及请求ID供显式重试核对；新会话清空旧会话命令，不将旧请求换身份重发。原业务回执仍保留在服务器。

迁移范围、来源与验收结果见[管理与作业界面迁移记录](../docs/development/management-ui-migration-2026-10-23.md)，早期复用依据保留在[逐项复用审查](../docs/architecture/edhr-reuse-audit.md)。后端受控文件默认路径相对启动工作目录；使用仓库根目录启动可固定为根目录`var/controlled-documents`，从其他目录启动时应显式设置绝对`mes.document-storage`路径。

| 目录 | 用途 |
| --- | --- |
| `src/` | 应用入口、路由、页面、公共组件与业务接口调用 |
| `public/` | 无需打包处理的公共静态资源 |

生产执行采用标准功能页面与业务配置。普通页面录入组件可以复用；不引入通用表单设计器、DHR 填报引擎或电子签名认证流程。

开发依据：[产品蓝图](../docs/product/blueprint.md)、[行业详细设计](../docs/product/pack-domain-design.md)、[开发与验收契约](../docs/development/contracts-and-acceptance.md)。
