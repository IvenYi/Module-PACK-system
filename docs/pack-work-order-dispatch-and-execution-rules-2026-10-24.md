# 工单、派工与人员执行业务规则 v0.3

日期：2026-10-24。状态：**业务讨论稿；不是实施完成或验收记录。**

本轮只梳理流程与规则，不修改业务代码、数据库和运行数据。依据 `Module-PACK-system` 仓库的当前 Pack 源码、同仓库产品规划及本轮用户选择编写。文中的“建议”仍需业务确认，不能视为已经交付。

## 1. 本轮已经明确的范围

用户本轮明确选择：

1. **先按一张工单指定一条主产线梳理。**
2. **任务派到工位，由有权限的人员登录执行，不要求提前绑定具体个人。**
3. **自产模组／PACK 尚未统一 SN 来源，默认由本系统生成 SN。**
4. **工单计划数量表示目标合格产出数量；报废补投另行批准。**
5. **现场换单模式尚未确定，本轮先把“整线统一换单”和“按工位换单”两类规则写清，不预设允许混单。**

本版在上述已确认选择下细化产品工艺与资源联动、派工层级、任务接收／切换和多工单并发，同时保留 SN 建档、投产额度、报废补投及结案规则。具体岗位与控制条件仍按下文建议讨论，不把已确认的原则扩大为全部细节均已确认。

据此，本轮主流程为：

**工单建立／同步 → 核对生产依据 → 选择主产线并安排各工序工位 → 下达派工 → 工位显示任务 → 人员登录、准备并扫码开工 → 按 SN 逐工序流转 → 制造完工 → 质量放行 → 工单结案。**

“一条主产线”是本轮设计范围，不表示一张工单只有一个工位。完整产品规划中的同单多线分量派工保留为后续扩展，本轮不要求实施该分配模型。正常工序先按主产线内工位安排；共享检测、线外资源和跨线工序若为现场必需，需要单独明确，不能靠任意选工位绕过派工。

## 2. 先把几个概念分清楚

| 概念 | 业务含义 | 不应混淆的关系 |
| --- | --- | --- |
| 工单 | 确定生产什么、多少、使用哪个制造版本及计划时间 | 工单是生产要求，不是某个操作员的个人待办 |
| 工厂／车间／产线／工位 | 工位属于产线，产线属于车间，车间属于工厂 | 行政部门、人员班组与生产资源不是同一层级 |
| 工序 | 如装配、绝缘测试、终检，规定要做什么和前后顺序 | 工序不是物理地点；同一工位可在不同任务中执行适用工序 |
| 适用工位 | 制造版本允许执行某道工序的工位范围 | “能做”不表示“本次已安排来做” |
| 派工安排 | 将这张工单安排到主产线、计划窗口，并明确各工序的实际工位 | 本轮不拆成多条线的数量分配，也不预先指定操作员 |
| 工序任务 | 派工下达后，每个执行工位收到的某张工单、某道工序的任务 | 不是给每道工序再创建一张独立工单 |
| 单件 SN | 每一台／个实物的唯一身份，关联工单、制造依据及制造履历 | 产品料号表示型号，工单号表示一批生产要求，都不能代替单件 SN |
| 工位任务上下文 | 当前工位正在执行哪项任务，采用什么版本，准备是否完成 | 不能只靠浏览器记住一个工单号代表正式开工 |
| 单件进站 | 某个 SN 在某工位开始某道工序的一次实际执行 | 查看任务、切换详情、查看工序均不产生进站事实 |

制造版本保存“允许的工艺和资源范围”；派工记录“本次安排”；单件执行记录“实际在哪里、由谁、何时、依据哪个版本做了什么”。三者都要保留，后续改派不能改写既有执行事实。

### 2.1 产品有了路线，怎样联动产线和工位

建议按以下关系组织，不把产品直接永久绑定到唯一产线：

| 层次 | 明确什么 | 怎样传递到下一层 |
| --- | --- | --- |
| 产品及产品版本 | 要制造的型号／规格 | 选择适用工厂中已发布的制造版本，不仅凭产品名称猜用哪套工艺 |
| 工艺路线版本 | 有哪些工序节点、按什么顺序执行 | 每个节点有独立身份；名称相同的前测、复测等节点不能合并为一道任务 |
| 制造工艺配置／制造版本 | 每个路线节点的动作、参数规范、SOP、运行模式和适用工位；同时冻结 BOM 等依据 | 得到该产品各节点“允许在哪做、按什么要求做”的范围 |
| 工单及派工 | 本次产品、版本、数量、主产线及各节点实际工位 | 从允许范围中选择本次资源，形成具体工位任务 |
| 工位任务与实际访问 | 工位当前做哪个任务，哪些 SN 可进站，实际由谁执行 | 按本次任务的冻结依据记录装配、检验、过站和资源使用 |

因此，知道产品有三道工序还不够：工艺人员要为三道节点配置适用工位，派工人员再确定本次分别采用哪个工位。工位在工厂建模中有真实归属，系统据此反推出哪些产线能覆盖这套工艺，不需要为了本次派工再建立一套重复的产品—产线台账。

例：某制造版本配置如下，编号仅为规则说明：

| 路线节点 | 制造版适用工位 | 选择A产线时的实际工位 |
| --- | --- | --- |
| 10 装配 | A01、B01 | A01 |
| 20 检测 | A02、B02 | A02 |
| 30 终检 | A03 | A03 |

A线覆盖全部节点，可以形成完整派工；B线缺少终检资源，不能因为装配和检测能做，就将整单派到B线并临时借用A03。本轮正常派工不默认跨线；确有共享终检时先明确共享资源及派工规则。

同一工位可以被配置为多个产品、多个路线节点的适用资源，但每次加工采用当前具体任务的版本及规范，不能沿用上一产品的参数。工艺能力、任务安排和资源当前忙闲是三件事：当前忙碌可以影响开工时间，不应把合法工单排队也当成工艺不支持。

## 3. 谁负责哪一段

| 角色 | 负责事项 | 业务边界 |
| --- | --- | --- |
| 工艺／产品人员 | 发布制造版本，明确路线、各工序动作、适用工位、SOP、检验规范和执行模式 | 新版本不覆盖在制品的原制造依据 |
| 计划人员 | 手工建立或核对同步工单，确定产品、数量、日期及主产线需求 | 外部工单信息与内部执行状态分开管理 |
| 生产负责人／班组长 | 安排并下达工位任务，调整先后顺序，处理生产暂停、恢复及受控改派 | 可以由同一人兼任计划，但业务权限分别明确 |
| 操作员 | 登录工位，查看本工位任务，准备、扫码、按动作执行并提交结果 | 不能随意改产线、工序、数量、制造版本或强制放行 |
| 质量人员 | 处理 NG、质量锁定、返修授权、复测要求及质量放行 | 生产暂停与质量锁定分别处理，生产恢复不能解除质量锁定 |
| 设备／外部产线 MES | 按约定主责执行或回传对应任务、SN、工序的真实结果 | 不能与人工端对同一业务事实重复过站、绑定或报产 |

不要求派工时指定个人，不代表所有有登录账号的人都能操作。至少检查业务权限、所属工厂及该工位的操作授权。人员技能证书、排班考勤等不在本轮自动扩展；现场确有要求时再纳入资格规则。

## 4. 从建立工单到任务下达

### 4.1 建立或同步工单

建议工单至少包括：工单号、来源、所属工厂、产品、计划数量、已发布制造版本、计划开始／结束时间，以及来源工单号和来源版本（外部同步时）。生产备注可以补充，但不能代替结构化的数量、版本和资源安排。

处理规则：

1. 手工建立和外部同步最终进入同一套内部工单规则。
2. 创建成功表示生产要求已建立，不表示现场已经开工。
3. 产品、工厂、制造版本等映射不完整时，工单保持“待核对”，显示具体问题；不能用默认版本或随便选一个工位代替核对。
4. 核对通过后进入“待派工”。若外部已经给出产线／工位安排，可带入派工草案；只有来源被授权且通过全部下达校验，才可直接成为有效派工。
5. 工单核对时固定制造依据；派工下达时再次检查其适用性和资源状态。工艺内容一经被派工或单件引用，不通过普通编辑静默替换。

同步不等于覆盖：按“来源系统＋来源范围＋外部工单标识”识别同一工单，重复消息不新增工单；来源状态、接收状态和内部执行状态分别保存。外部取消或完工通知只是待处理的业务请求，不能直接抹掉本地在制或把本地改成已完工。

### 4.2 怎么派工、派到哪里

本轮建议由生产负责人在工单内完成一份派工安排：

1. 选择该工单的主产线，车间和工厂根据归属带出并核验。
2. 带出冻结制造版本的全部路线工序及执行顺序，不由派工人员临时增删工艺。
3. 每道工序从“制造版本适用工位 ∩ 主产线所属有效工位”中安排一个实际工位。
4. 只有一个合法工位时自动带出；存在多个时由派工人员择一。找不到合法工位时阻止下达，说明缺哪道工序的资源。
5. 填写计划窗口和任务优先顺序；班次可作为已有排班信息的辅助字段，不强制先建设班次或排班系统。
6. 核对后执行“下达派工”，一次形成各工序的工位任务。

本轮先采用“每道工序明确一个实际工位”的建议规则。多个候选工位不代表同一 SN 要逐一加工，也不默认允许操作员在候选工位间任意选择。需要同工序多工位分流时，再明确分流和数量规则。

派工选择主线时，应展示各必要路线节点的合法工位交集及缺项原因；不能只列出所有同厂产线让人员盲选。静态资格满足后，即使产线／工位正在做另一工单，也可按队列规则下达后续任务，实际启用仍受第5.8节的换单和资源占用约束。

例如同一张工单的派工可以是：

| 工序 | 实际安排 | 工位收到的任务 |
| --- | --- | --- |
| 10 装配 | A 产线／装配工位 A01 | 工单 WO-001 的装配任务 |
| 20 检测 | A 产线／检测工位 A02 | 工单 WO-001 的检测任务 |
| 30 终检 | A 产线／终检工位 A03 | 工单 WO-001 的终检任务 |

上述编号只用于解释规则，不是现场工艺或真实资源配置。

### 4.3 下达前校验什么

至少确认：

- 工单信息完整，未取消、未结案，计划数量有效。
- 制造依据明确，路线可执行，所需动作和规范已发布。
- 主产线有效且属于本工单工厂；每道工序都有合法的实际工位。
- 工位安排符合制造版本和执行模式；未授权的跨线工位不能混入。
- 每道工序的执行主责明确；外部 MES 工序已明确具体接收系统及版本映射。
- 新的派工修订没有覆盖已开工单件和既有执行事实。

下达前检查的是任务和配置能否成立；现场物料、工具、程序及首件等准备在工位开工前按适用项检查。不能把“派工已下达”当成“准备已完成”。

### 4.4 派工最终下达到什么层级

**本轮派工到“主产线＋该线内的各工序实际工位”两层，不只停在产线，也不直接派成个人待办。**

| 层级 | 在派工中的职责 | 是否是人员执行的最终任务 |
| --- | --- | --- |
| 工厂／车间 | 授权范围及组织归属 | 否，不能只选车间就让所有工位自由做 |
| 主产线 | 承接整张工单的生产安排、计划窗口和线级换单规则 | 是工单归属，不足以单独确定每道工序由谁做 |
| 路线节点＋实际工位 | 明确某工单某一道工序实际在哪执行 | 是，形成工位队列中的工序任务 |
| 人员 | 接收／启用任务和提交实际动作的登录主体 | 不提前强制指定个人；按授权执行并留真实人员记录 |
| 设备／通道／治具 | 该任务执行时需要的物理资源和实际占用 | 不能代替工位任务；共享资源另核验，任务下达不代表已占用 |

人员在派工界面选择主产线后，系统展开路线，自动带出唯一合法工位，多个候选时让派工人员择一，最后统一校验、下达全部工序任务。不是让操作员到现场再自行猜选工位，也不是把全部工序都“接给一个工位”。

工序任务至少可反查工单、制造／路线版本、具体路线节点、实际工位、正常／补投工作量和有效派工修订。同一工单的两个节点即使都安排A01，也形成两个不同工序任务；不能按工单号合并。修订或补投的差异可追溯，不重复下达原来已执行的工作量。

## 5. 人员到了现场怎么执行

### 5.1 登录与看任务

操作员登录个人账号，进入被授权的工位；固定终端可预设工位，但登录人和工位都由服务端核验。工位切换不改变原任务和单件历史。

工作台首先显示“本工位任务”，至少包含工单、产品、制造版本、工序、计划数量、可做／待前序数量、在制数量、工序完成数量、计划窗口、优先顺序和暂停提示。后序工位可以提前看到已下达任务，但其中尚未满足前序的 SN 不能开工。

“已下达队列”“当前任务”“本件是否可做”分别显示。一个工位可有多项已下达任务，某个任务也可同时有已完成、可做和待前序的不同 SN；不能因任务在列表里就允许所有件进站，也不能因部分件未到就把整个任务隐藏。

操作员不需要从全厂工单里猜测该做哪张，也不能靠扫描一个 SN 自动获得任意工单／工位执行权。允许查询其他记录的权限与允许执行的权限分开。

### 5.2 “接单”在这里承担什么作用

建议把接单放到工位执行环节，表示工位确认执行已派给自己的工序任务，不在工单管理中再选一个“接单工位”代替完整派工。派工下达使任务进入工位队列，启用／接收任务才建立有效现场上下文，单件进站才产生实际生产事实。

建议的简化交互为：

- 查看或选择任务只预览其内容，不切换服务器保存的当前任务，也不写接收、开工或换单记录。
- 没有需结束的旧上下文、且符合产线换单规则时，人员准备完成并首次点击“开始作业”，系统可一并核验、记录任务接收和该 SN 的实际开工，不再增加一轮纯确认按钮。
- 如果现场需要提前接收但稍后开工，保留“确认任务／开始准备”，并分别展示接收与实际开工时间。这是可选现场规则，当前不默认强制。
- 重复选择正在执行的同一任务，返回原上下文，不重复建任务、触发换单、清料或首件。

需要正式开始准备时可启用对应任务，记录接收人、接收时间及准备状态，但仍不算单件投产。整线模式下先由生产负责人或获授权人员启用本线当前工单，各工位只能启用该工单的有效任务；工位模式下，由获授权人员在本工位队列中按安排启用任务。已有另一当前任务时必须走第5.8节的受控切换，不能用“开始作业”绕过。

“任务接收”不是员工把整张工单占为个人任务。任务仍归工位；每次实际动作记录对应登录人。

### 5.3 生产准备

按制造版本和现场适用规则检查物料／子件到位、工装与设备状态、程序／配方版本、SOP及首件等。纯人工工序只检查适用项，不要求虚构设备回执。未配置的现场标准不得编造为已通过。

同一工位可排多项待执行任务；本轮建议同一实际作业单元只有一个有效的当前任务，首版未明确独立单元时就按整个工位控制。整线是否另有限制，按第5.8节事先定义的产线模式校验。设备多通道若要独立执行不同任务，必须先证明可独立换型、隔离资源及关联结果，不能仅凭开两个浏览器获得并发资格。

### 5.4 SN 在哪里建立

#### 5.4.1 谁提供 SN

自产模组／PACK 默认由本系统发号，是用户已确认的原则。以下为具体落地建议：

| 对象／来源 | 建议身份规则 | 与工单的关系 |
| --- | --- | --- |
| 本厂自产模组、PACK | 使用本系统按已发布编码规则生成的主 SN | 每件关联一张生产工单和制造依据 |
| 来料电芯、外购模组 | 接收时记录原厂／供应商码；可可靠唯一识别时受控采用，否则生成内部主 SN 并保留来源码关联 | 关联接收来源，不强造内部生产工单 |
| ERP、客户或产线 MES 提供的其他编码 | 默认保留外部编码关联，不与本系统同时为同一实物各建一件；如未来约定外部发主码，先明确产品／来源范围及发号主责 | 接收同一身份的重复消息不新增单件；来源冲突进入核对 |

同一实物只有一个有效主身份。箱码、托盘码、物料批次码、工单号和型号不能直接代替单件 SN。供应商码若在声明的来源范围内也不能唯一解析，需补来源信息或隔离核对，不能任意关联到同码物料。

建议主 SN 至少在“租户＋工厂”内唯一，并使标签／查询上下文可以可靠确定该范围；跨厂不能按裸码猜测身份。SN 作为字符串保留前导零，格式、大小写和扫描解析规则由版本化编码规则约定，不在本讨论稿硬编码码长或具体流水格式。

号码允许断号；不能为补齐流水复用已发出、已作废或曾被使用的号码。

#### 5.4.2 默认在何时建档

**建议默认时点：派工已下达、制造依据已核对后，由生产准备人员按需要生成一批 SN，并同步建立“已建档、未投产”的记录，然后打印／贴标复核。** 不必工单一同步就一次生成全部号码。

| 时点 | 系统应记录什么 | 是否已经生产 |
| --- | --- | --- |
| 工单建立／同步 | 生产要求及制造依据；此时不自动批量创建 SN | 否 |
| 派工下达后的生产准备 | 在有效额度内发号并建档，关联工单、产品、制造依据和派工；占用未投产预留数 | 否 |
| 打印、贴标及扫码复核 | 打印内容、结果、贴标核对及重印原因等适用记录 | 否；打印成功也不能证明实物已开工 |
| 首道正式工序进站 | 校验标签与任务，将该 SN 从未投产预留转为已投产，并建立实际访问 | 是 |
| 后续过站、复测和返修 | 继续同一 SN 的访问与动作履历 | 不重复计算首次投产 |

发号和有效建档应作为同一次业务处理：失败重试查询原请求结果，不另外发一批号码。标签可按需小批量准备；首站现场需要新码时也先走受控发号、建档和贴标核对，再正式进站。**本轮不建议将“扫描任意未知码”作为自动创建生产单件的入口。**

来自外部的未核对身份可以保留接收记录，但不能因此取得正式投产权。原料接收建档也不自动证明来料质量合格。

#### 5.4.3 建档后锁定什么

1. 首站正式进站前，SN 必须唯一，归属本工单，引用核对后的产品及制造依据。
2. 一单一主线下，SN 归属该工单的派工安排，不给每道工序另建一件或另分配一个 SN。
3. 自制模组可先由模组工单生产，再投入 PACK 工单；保留来源工单、目标工单及装配关系，不能把模组的生产工单改成 PACK 工单。
4. 已有 SN 引用的工艺依据不随普通编辑改变；需要变更时核对受影响件、标签和任务，保留原基线及变更。
5. 正常返修、换电芯、换模组和标签重印均沿用父件原 SN。是否报废整件，由质量处置明确决定。

#### 5.4.4 重印、作废与错码

| 情况 | 建议处理规则 |
| --- | --- |
| 打印失败、网络超时或重复点击 | 核实并复用原 SN 和打印任务；不重复发号或新增一件 |
| 标签损坏，需要补打 | 重印同一个 SN，记录原因与次数，处理旧标签，不增加投产额度 |
| 已建档但确实尚未投产，取消使用 | 作废该未投产 SN，撤销其生产资格并释放预留，原号码永不再分配 |
| 预建 SN 作废后需要另一个号码 | 在释放的原预留额度内重新发号；不批准一次新的补投额度 |
| SN 已实际投产，后发现标签／归属问题 | 进入受控更正或质量处置，不能删除记录、直接改号换单或按未投产作废 |
| 页面没有进站，但实物已经加工、装配或发生消耗 | 先按真实事实核对并补齐受控记录，不能按“未开工”作废以释放额度 |
| 已使用或已作废号码再次扫码 | 显示原记录和状态，按任务资格拒绝非法投产，不复活为新件 |

取消工单、减量或结案时，未用标签也要对应处理。历史发号和作废记录保留，因此“历史建档总数”可以大于有效预留数或计划数；不能仅数数据库里有多少行就判断超投。

### 5.5 扫码开工

操作员选择本工位的有效任务，扫描待加工 SN，确认开工。服务端至少检查：

| 检查项 | 不满足时 |
| --- | --- |
| 当前账号、工厂和工位操作权限 | 拒绝操作，保留明确原因 |
| 工单与派工有效，未被生产暂停或撤回 | 不允许新进站 |
| 任务已合法启用，符合整线／按工位换单范围，且实际资源可用 | 已下达排队不等于可开工，不抢占另一有效任务或共享资源 |
| 正常生产符合当前有效派工；受控返修符合独立授权的目标工序／工位；两者均满足制造依据及合法变更范围 | 拒绝未授权的串线／串工位执行，不用普通派工拦截合法返修 |
| SN 属于当前工单和生产安排，产品及版本相符 | 拒绝混单，不自动更换当前任务 |
| 前序完成，当前工序尚未正常完成，SN 未在其他工位活动 | 拒绝跳站、重复加工或抢占 |
| SN 质量状态允许；返修时存在有效授权 | 普通开工不能绕过质量锁定 |
| 准备项、适用资源和执行主责满足 | 提示具体缺项，不能假完成 |

正常生产按上述普通工单及派工规则校验；受控返修的任务有效性、回站路径、已完成工序重入和复测要求按独立返修授权校验。身份范围、SN唯一、活动占用、证据来源及产线／共享资源互斥约束仍共同适用。已结案原工单仅供溯源，独立返修不恢复其普通派工、发号、补投或生产权限。

成功后建立该 SN 的本次工位访问，记录工单、任务、工序、工位、制造依据、派工／返修依据、开始时间及实际人员。正常生产的工单首次真实开工才进入“生产中”；独立售后返修记录在新返修任务中，不重开原生产工单。

### 5.6 执行、出站和流转

1. 加载该工序的 SOP 和必需动作，操作员按动作装配、测量或检验。
2. 装配检查子件型号、层级、质量、位置、方向和占用；检验保存原始值、来源及判定。人工输入不能冒充设备采集。
3. 同一 SN 的动作按发布规则完成；通信重试不重复绑定、记账或计产。
4. 所有必需动作及有效证据满足后，才能正常完成当前工序。
5. 当前访问结束，该 SN 成为下一工序的待执行件；下一工位扫描同一个 SN 继续。
6. 当前件可流转，不要求整张工单在前站全部完成后才允许后站生产。不同 SN 可以同时分布在不同工位，形成流水生产。
7. 同一 SN 已完成的正常工序不能随意重复进站；回站加工按受控返修执行。

本轮正常路线先沿用顺序工序链。多 SN 同时流水作业，不等于同一 SN 的工艺分支／并行路线；后者仍需独立工艺规则。

### 5.7 多人协作与接班

任务派到工位，不强制原开工人独自完成。其他有权限人员可以按交接规则继续原任务／原 SN，每次提交记录自己的真实身份，不借用账号，也不覆盖前人的记录。

交班前核对当前 SN、未完成动作、未保存输入、异常和未决设备运行；接班人登录后恢复服务器已保存的上下文。页面草稿不能假装已经提交。通信结果未知时先核实原请求，不能重新建单件或另发一次加工。

对同一 SN 的冲突提交要拒绝或要求刷新；多人共用工位不表示可以并发重复完成同一动作。设备正在运行时是否允许人员离岗、如何交接，按现场设备规程另定。

### 5.8 一条产线能做几张工单，人员怎样切换任务

#### 5.8.1 先区分排队、当前任务与实际加工

**一张工单只派一条主线，是工单去向限制；不是“一条线只能接一张单”。** 一条线、一个工位都可以有多项已下达任务排队，任务下达不等于启动加工或预占设备。

建议分开记录：产线／工位待做队列、有效运行上下文、SN实际访问，以及设备／通道／治具占用。不能仅靠一个“当前工单”字段代表以上所有状态。

同一工位的当前任务应明确到“工单＋制造／路线版本＋路线节点＋有效派工／补投依据”，并包含实际工位。重复选择同一有效任务才按原上下文返回；同一工单节点10与节点30不是同一个任务，不能因工单号相同而跳过工序切换校验。

#### 5.8.2 两类换单模式及控制层级

现场模式尚未确定。建议在每条产线投入使用前明确以下一种控制规则，而不是让操作员每次临时决定；模式变化也须核对已有运行上下文及共享资源，不影响已发生事实。

| 项目 | 整线统一换单 | 按工位换单 |
| --- | --- | --- |
| 适用前提 | 例如全线共用型号／配方、输送或联动加工，无法可靠隔离不同工单 | 各工位可独立切换，工艺／缓冲／实物标识支持不同工单在不同站并存 |
| 可以派来多少单 | 多单可排队 | 多单可排队 |
| 同时运行范围 | 一条线只有一个有效运行工单；各站当前任务必须属于它 | 每个独立作业单元只有一个当前工序任务，不同工位可属于不同工单 |
| 工位能否自行换另一单 | 不能，须先完成整线受控换单 | 可在授权和准备条件满足时受控切换，不要求其他独立工位同时换单 |
| 前单尾件与后单首件 | 不能同时在受控线内正常加工 | 条件满足时可在不同工位同时加工 |
| 前单暂停后 | 不自动释放整线当前工单和设备占用 | 不自动释放本作业单元的当前任务及资源占用 |
| 换到下一单前 | 核清受影响线内在制、活动访问、运行和未知结果，处理余料与换型准备 | 核清本作业单元及其共享资源范围，再处理本任务余料与换型准备 |
| 是否要等前单结案 | 不需要；前单可留待放行／结案，但必须离开受影响加工范围且有明确去向 | 不需要；其他工位可继续前单，但必须满足物理隔离和共享约束 |

未明确模式和物理边界时，可以安排待做队列，但不能仅凭工位不同就自动授予多工单混线加工资格。按工位模式也不默认允许每扫描一个不同工单的 SN 就自动切单。

#### 5.8.3 按工位模式下的具体例子

两张工单各2台，从工艺配置、派工、人员接收和逐件执行，到整线／按工位切换及质量收尾的完整过程，见 [同线双工单完整业务示例](pack-two-work-orders-one-line-walkthrough-2026-10-24.md)。以下为简要关系说明。

同一产品的工单A、B都派到同一主产线，均经过A01装配、A02检测、A03终检。在已确认支持按工位换单并完成必要准备的前提下，可以出现：

| 时段 | A01装配 | A02检测 | A03终检 |
| --- | --- | --- | --- |
| 时段1 | A | A | A |
| 时段2 | B的首件／后续件 | A的尾件 | A的尾件 |
| 时段3 | B | B | A的尾件 |
| 时段4 | B | B | B |

A、B仍各自只对应这条主线，但这条线在时段2、3同时有两张工单执行。每个站只做自己的当前任务，每件仍沿用原SN、原工单及版本，数量分别累计。相同产品的两张工单也不能合并实物身份和生产记录。

如果是整线统一换单，时段2、3不允许：先将A受影响线内的加工收尾或按授权移出并明确去向，再统一启用B。A尚未投入的剩余量可以保留排队，不能因换到B就自动判A全部完成或取消。

不同产品能否这样并存，还需满足各自制造版、独立配方、物料／治具隔离、缓冲位置及现场交接规则；不能从“同产品多工单可流水”直接推出任意混型号都可生产。

#### 5.8.4 从当前任务切换到另一任务

建议流程如下，适用于有权限人员操作，不增加无依据的审批步骤：

1. **预览目标任务。** 显示目标工单、产品、版本、节点和准备要求；旧任务仍是服务器当前任务，不清空已保存记录，未保存输入先保存或明确放弃。
2. **确定影响范围。** 整线模式检查整线当前工单；工位模式检查本作业单元及关联共享资源。任务未下达、被暂停／撤回或不属于该资源时不能启用。
3. **处理当前实际加工。** 正常结束当前件／批，或走合法的中止、移交／返修流程；仍在加工、无法确认已停止、结果未知或活动访问尚未妥善结束时，不直接换单。
4. **处理现场与准备差异。** 核对在制及位置、余料归属、工具／治具、程序／配方、SOP与适用首件。哪些准备需重做按发布规则及本次变更确定；不因同型号就默认全部免检，也不要求无条件重做所有首件。
5. **结束旧运行上下文，启用目标上下文。** 在一次受控处理中更新有效当前任务／整线工单，保留切换人、时间、原因及前后依据；失败时不得出现两个同时生效的当前任务。
6. **核验目标任务并继续扫码。** 切换成功才允许目标SN进站。原工单／原SN的装配、消耗、检验和产量归属不变，未知或晚到结果按原运行关联，不归给新单。

重复发起同一次切换应返回已确认结果；响应不确定时先核实原切换，不能另发一次制造或清料。以上控制作用于服务器现场上下文，同工位其他终端拿旧上下文提交时应拒绝或要求刷新，不能每个浏览器各自生效一张工单。

#### 5.8.5 换单、暂停、交班和切换查看不是同一件事

| 行为 | 是否切换正式当前任务 | 处理规则 |
| --- | --- | --- |
| 打开另一工单详情／预览任务／切换页面标签 | 否 | 只能查看，不改变加工授权和资源占用 |
| 当前任务内扫描下一SN | 否 | 同任务下逐件核验，不重复接收任务；SN不同不等于工单切换 |
| 同工单切到另一工序节点 | 是，若成为另一当前工序任务 | 检查节点、准备、前序与当前访问；不能按“同工单”直接沿用旧节点 |
| 工位切到另一工单任务 | 是 | 按换单模式和第5.8.4节处理，不能扫描即覆盖 |
| 换操作员／交班 | 通常否 | 沿用合法当前任务，核对未决事项，新增动作记新登录人 |
| 暂停任务／工单 | 否，不自动释放现场范围 | 阻止新的启动；不能暂停A后直接启用B绕过整线或设备占用 |
| 更换终端显示的工位 | 不替原工位执行换单 | 校验新工位授权和服务器真实当前任务，原工位的加工／占用仍存在 |

结束旧运行上下文不等于终止旧工序任务。旧任务剩余量保留待做／暂停和可恢复依据；之后A的尾件、后续重复节点、补投件或合法返修返回时，若工位当前在做B，应排到A对应任务并提示受控换回，不能自动串到B，也不能因曾切换就永久无入口。

#### 5.8.6 并发最后受什么约束

- 按工位模式允许不同站做不同工单，但共享程序、输送、设备、治具或通道可能要求更大范围互斥。相应共享范围从严校验，不因工位编号不同而忽略实际冲突。
- 同一当前任务可以按已明确容量处理多个不同SN；“一个当前任务”不等于“整条线一次只能有一个产品”。未明确设备／通道容量时不擅自声明支持多件并发。
- 同一SN不能同时在两个活动访问中加工；正常重复进站和返修重入分别按路线／授权校验。
- 多人可以接班或协作执行同一任务，各记实际操作人；不能各自启用互相冲突的任务或重复提交同一动作。
- 质量返修授权只允许走指定路径，不授予抢占正在为其他工单加工的设备、绕过整线换单或共享资源限制的权利。跨主线的返修需单独明确资源协调规则，本轮不视为自动可用。
- 人工、设备和外部MES均受有效派工、换单范围及唯一主责约束。外部MES主责范围由对方受控接收／切换，本系统不能靠人工选单制造第二份运行。

## 6. 数量和状态怎么计算

### 6.1 数量口径

**已确认：计划数量是目标合格产出，报废补投另批。** 为此，建议把合格目标与投产额度分开，不能再使用“所有历史建档数不得超过计划数”的简单规则。

| 数量 | 含义 | 关键规则 |
| --- | --- | --- |
| 目标数量 P | 本工单要完成的合格产出目标 | 普通报废补投不增大 P；目标变更另留批准和来源版本 |
| 投产额度 A | 允许首次投产的累计唯一 SN 上限 | 建议初始 A＝P；批准补投后增加，不能因报废自动释放已用额度 |
| 已投产 S | 曾经首次正式开工的唯一 SN 数 | 后续报废、返修、过站不减少或重复增加 S |
| 未投产预留 R | 有效建档并占额度、尚未正式开工的 SN 数 | 发号建档增加 R；首次开工 R 减一、S 加一；未投产作废减少 R |
| 当前合格 G | 本工单产出、制造完成且当前有效质量放行的唯一 SN 数 | 不含锁定、未决返修、已报废件；投入下游装配本身不撤销其合格产出事实 |
| 整件报废 D | 本工单已投产、经正式处置整件报废的 SN 数 | 只数本工单的产出层级，不把子件报废数当父件报废数 |
| 其他终止 T | 已投产、经批准以非合格非整件报废方式终止且去向已处置的 SN 数 | 不能把未处理在制随手归入 T 来凑结案 |
| 未决投产 U | 已投产但尚未归入 G、D、T 的件数 | 包含加工在制、待检、制造完工待放行、锁定及未决返修等 |

开放工单按每个 SN 的当前结果核对，G、D、T、U 互斥：

- **S＝G＋D＋T＋U。**
- **S＋R≤A；剩余可建档额度＝A－S－R。**
- 已投产件报废后仍留在 S 中，同时从原当前结果转入 D，不回收其已用额度。
- 当前合格件又被有效锁定／授权返修时转入 U；修复并重新有效放行后再回 G，不增加一个新产出身份。

U 是“未结清的已投产件”，不只是还在工位加工的件数。制造完工可以仍有待放行件，因此 U＝0 用于结案核清，不能当作制造完工的唯一条件。

例：目标 10 台，投产后整件报废 2 台，再批准补投 2 台：

| 时点 | P | A | S | R | G | D | U |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 生成首批10个 SN，尚未开工 | 10 | 10 | 0 | 10 | 0 | 0 | 0 |
| 原10台都已投产，8台合格、2台报废 | 10 | 10 | 10 | 0 | 8 | 2 | 0 |
| 批准补投2台并生成新 SN | 10 | 12 | 10 | 2 | 8 | 2 | 0 |
| 补投2台正式开工 | 10 | 12 | 12 | 0 | 8 | 2 | 2 |
| 补投件完成并有效放行 | 10 | 12 | 12 | 0 | 10 | 2 | 0 |

此时目标仍为 10 台，累计投产 12 台，整件报废 2 台，当前合格 10 台。工单不能因 S 大于 P 就误判超投，应检查是否超过获准额度 A。

各工序完成数、历史制造产出数、当前合格数和打印数量分别展示。某工序可能已有 12 个唯一 SN 完成，其中 2 个后站报废，最终合格仍为 10 台；各站数量不能相加成成品产量，复测也不新增产品数。

### 6.2 分层状态

下表为建议业务状态，不是要求立即替换现有数据库枚举。

| 层次 | 建议状态与含义 |
| --- | --- |
| 工单 | 待核对 → 待派工 → 待开工 → 生产中 → 制造完工 → 已结案；未开工且按规则处置引用后可取消 |
| 派工安排 | 草案 → 已下达 → 执行中 → 已结束；未执行安排可撤回，已执行部分保留 |
| 工位任务 | 已下达／待准备 → 执行中 → 已完成；其中每个 SN 另有待前序、可执行、活动访问等资格 |
| SN 生产状态 | 已建档、在制、制造完成、已终止等；实际流转由访问与动作记录证明，整件报废同时保留质量处置 |
| SN 质量状态 | 待判定、合格／已放行、锁定、返修等；与生产状态分开 |
| 同步状态 | 待发送、已收件、已确认、失败／冲突等；接口成功收件不等于派工已执行或产品已完工 |

生产暂停作为带范围和原因的独立控制：可以暂停工单、某工位任务或某件；暂停不清空工单的原进度。暂停、质量锁定、通信失败都不应塞进一个“未完成”状态而失去原因。

### 6.3 报废以后怎么补产

#### 6.3.1 先区分处理对象

| 情况 | 使用哪个 SN | 是否增加本工单整件投产额度 |
| --- | --- | --- |
| 检测 NG、质量锁定、等待判定 | 保留原 SN，进入质量处置 | 否；未判整件报废就不能按报废补投 |
| 原件返修、换电芯或换模组 | 父件仍用原 SN；拆出子件保留自己的历史和去向 | 否；子件报废不能自动换算为一台父件补投名额 |
| 本工单产出的整件明确报废 | 原 SN 终止正常生产资格，批准补产后使用新的 SN | 经独立补投批准才增加 |
| 未投产预建 SN 不再使用 | 作废该号码，释放未投产预留 | 否；可在原有效额度内另发新号 |
| 已结案产品售后返修或换新 | 返修沿用原实物 SN；新造替换件用新的生产工单和 SN | 不直接扩大原已结案工单额度 |

例如：PACK 内一只电芯报废并换新，PACK 继续使用原 SN；只有质量人员明确整台 PACK 报废，才可能申请补造一台 PACK。自制模组在下游被判整件报废时，影响其来源模组工单的数量核对；不能同时为来源工单和父 PACK 工单各自动增加一个补投名额。

整件报废时，建议质量人员明确 SN、原因、判定依据和实物去向，生产人员核对加工／设备是否已停止、未决结果和后续任务。原 SN 的未执行工序按报废终止，退出待做队列，已做记录、原始检验和装配历史保留。报废父件不等于其内部所有子件都可复用或都被报废；拆解和回收逐件受控处理，不自动释放合格可用子件。

#### 6.3.2 补投申请、批准与执行

建议采用以下顺序：

1. **确认整件报废。** 只有本工单已经投产且完成整件报废处置的 SN，才形成可申请的报废补投依据。
2. **生产负责人申请。** 指明原工单、报废 SN、申请补投数、原因、当前目标／投产／合格／未决数量及派工安排，不只填写一个“补几台”。
3. **质量核实，计划／生产授权岗位批准。** 核实确属整件报废、未重复补投、目标缺口和制造依据有效；质量判废不自动批准生产补投。
4. **增加投产额度。** 同一批准仅生效一次，更新 A，不把普通报废补投写成目标 P 增量。
5. **生成新的 SN 并建立补投工序任务。** 新 SN 关联原工单、原报废件、补投批准和有效派工；本轮仍在原主产线安排。按制造要求从必要的首工序执行，不能继承原报废件的加工合格记录。
6. **按正常生产与质量规则执行。** 新 SN 单独检验、放行，满足原工单目标；补投记录可追到最后结果。

原已完成的工序任务及证据不改成“从未完成”。补投形成明确的新增工作量及任务，后站不再等待已报废原件，也不会因为原任务曾完成就找不到补做入口。

如果工单已标记制造完工但尚未结案，之后判废并批准补投，应保留原制造完工历史，并将当前生产进度更新为有新增补投任务的待开工／生产中，不能保持“全部生产已结束”同时继续普通加工。

#### 6.3.3 防止重复补投和越量

- 建议一个已报废 SN 最多提供一个有效补投名额，批量批准时逐件关联；重复审批、点击、重试或外部回传返回原结果，不再次增加 A。
- 同一补投名额不能同时分配给两个新 SN；新 SN 尚未投产即作废时，可以在原名额内重新发号，不再次增加 A。
- 补投件正式投产即消耗该次名额。若再次整件报废，凭新的报废 SN 另申请下一次补投，保留完整的补投链。
- 尚在锁定／可返修状态的旧件不按“整件报废”先补投，以免旧件修复后形成超目标产出。
- 撤销尚未使用的补投批准前，先处理其预建 SN 和任务；已消耗的投产额度不能直接撤回，A 不能小于 S＋R。
- P 的增减与 A 的增减分别控制；目标变更核对来源授权、已合格及未决件的去向，不能再用“P 不得低于 S”限制正常的报废补产。
- 误判报废需要独立更正并核对已批准／已投产补件；不允许直接把旧 SN 恢复合格而忽略补投和结案差异。具体更正由受控质量处置决定。
- 本稿默认不允许未经批准的超产。发现实际已加工超额度时仍保留真实事实并进入差异处置，不能丢弃记录或修改计划掩盖问题。

### 6.4 完工、放行与结案

#### 6.4.1 三种“完成”不能合并

- **工序完工**：该 SN 当前工序正常完成，不关闭整张工单。
- **制造完工**：单件必要工序及证据完成；工单生产任务已按有效计划和批准处置收尾，无遗留活动加工。仍可有制造完成、等待质量放行的件，页面要显示“待放行”。
- **质量放行**：依据当前有效检验、装配和异常／返修状态确认单件合格，保留放行时快照；制造完工不能自动放行。
- **工单结案**：生产、质量、数量和必要接口／交接均已核清，并由有权限岗位确认封存该次执行结果。达到计划数量不触发自动结案。

未达到目标且仍决定停止生产时，先完成停止／短结批准及在制处置，再标记生产已收尾；不能直接改小原计划伪装按原目标完工。

#### 6.4.2 建议的正常结案条件

下列条件同时满足，才允许正常结案：

| 核对项 | 建议通过条件 |
| --- | --- |
| 合格目标 | G 达到有效目标 P；若 G 大于 P，超产差异须已有明确批准，保留目标和实际差异 |
| 已投产件全部有去向 | U＝0，S＝G＋D＋T；不存在加工在制、待检、待放行、锁定或未决返修件 |
| 未投产号码清理 | R＝0；剩余预建 SN 作废或按批准明确终止生产资格，未用标签已处理，号码保留不再用 |
| 额度与补投 | S＋R≤A，补投批准及新旧 SN 关联完整；没有重复批准、超额投产或待更正差异 |
| 工位与设备 | 无活动访问、未结束加工或结果未知的设备运行；各工序任务、补投任务已完成或按批准终止／撤回 |
| 质量事项 | 原 NG、整件／子件报废、返修和终止均已有最终处置，交付计数件放行证据仍有效；报废或终止不能仅靠改状态清账 |
| 接口与交接 | 影响本单数量、版本、质量和必需交接的消息／凭证均核清，无未决业务冲突；不以 HTTP 成功冒充业务确认 |
| 结案确认 | 有权限岗位确认原因、数量和必要批准，保存当时版本、SN清单、处置及回执摘要 |

未使用的剩余额度在结案后失效，不能继续发号或投产。非本单必需的辅助通知失败不应无限阻止结案；哪些外部回执是必需项，应在项目职责中明确，但凡影响数量和质量真实性的未知状态必须先核对。

#### 6.4.3 足额、短结与取消

| 情况 | 建议结案方式 | 保留什么 |
| --- | --- | --- |
| 达到合格目标，其他条件全部满足 | 正常足额结案 | 有效目标、实际合格／报废／终止／投产数及完整 SN 履历 |
| 已投产，但决定不再补足目标 | 先批准短结，再按其他相同清账条件结案 | 原目标 P、实际 G、不足数 P－G、原因和批准；不改小目标消除差异 |
| 已投产，最终合格为0且全部有最终去向 | 按批准生产终止／零产出短结 | 投产、报废或其他终止事实，不伪装成未生产取消 |
| 从未实际投产，S＝0 | 撤回任务，处理 R 和标签后取消工单，停止发号并使未用额度失效 | 原计划、取消原因、预建／作废记录；不生成合格产量 |
| 有在制、待放行、未结异常或未知运行结果 | 不能结案 | 显示具体阻断清单，继续处置 |

短结只批准“不再达到原目标”，不豁免质量、在制、标签和接口核清。建议生产负责人发起，质量岗位核清处置，计划／生产中具备结案权限的岗位确认；短结及目标变更由计划授权岗位批准。是否需要额外的独立双人审批按现场约定，不在本轮默认增加。

如果工单来自 ERP 等外部系统，短结、取消及结案还要按双方约定同步状态和数量；外部要求关闭不直接跳过本地清账，技术收件也不代表对方业务结案已确认。接口责任和必需回执属于项目需明确的边界。

#### 6.4.4 结案后发生什么

1. 原工单停止普通发号、补投、派工和生产命令，不能直接在已结案单追加一台产品。
2. 保存结案时的 P、A、S、G、D、T、SN结果、制造／派工版本、补投／短结批准和结案人员时间，不随后续主数据或质量变化改写。
3. 售后返修沿用原实物 SN，建立新的受控返修任务；需要制造一台替换件时另建关联生产工单和新 SN，保留原单及替换关联。
4. 结案后发现原件质量问题，可以产生新的锁定、追溯和处置；“当时已结案／已放行”的历史仍保留，同时明确展示当前质量状态。不能因历史结案就允许不合格件交付。
5. 晚到设备／MES消息先持久保留、去重并关联原任务。重复消息不改数量；新的冲突事实进入更正／追溯处置，按需补充外部更正回执，不自动重开或覆盖原结案快照。
6. 本轮默认不提供普通“重开工单”按钮。结案误操作或事实更正采用独立授权更正记录，保留原结案及后续修订；不能用删除旧结案的方式继续生产。

## 7. 暂停、换单、改派和取消

| 情况 | 建议处理规则 |
| --- | --- |
| 尚未下达 | 可编辑派工草案；制造依据变更仍须核对引用和 SN |
| 已下达但尚未开工 | 有权限人员撤回原安排，调整后重新下达；保留前后差异和通知，旧任务失效 |
| 已有单件开工，修改某道后续工序工位 | 先暂停受影响任务，核对每个 SN 的工序位置、活动访问及未决运行；生成新的派工修订，仅影响明确范围内的后续执行，已完成工位和证据不变 |
| 当前工序尚在加工，需要换站 | 不直接修改工位字段；先确认物理加工停止或完成，记录中止／转移及质量处置，释放有效资源后再受控续作，禁止重复加工 |
| 更换主产线或制造版本 | 不能当作普通派工编辑。本轮建议已有投产即阻止直接更换，进入专门变更处置；未来跨线转移／接管需另定规则 |
| 当前工位换另一工单 | 先按第5.8节确定整线或工位及共享资源影响范围，核对活动 SN、设备运行、未决结果、余料和准备项；受控切换运行上下文，保留旧任务剩余量。既有消耗、装配和产量留在原单 |
| 生产暂停／恢复 | 暂停阻止新的进站／加工启动，但不自动释放整线当前工单、当前任务或资源；已启动设备按安全规程停止或完成并保留真实结果。恢复重新检查条件，不重建 SN，不清除质量锁定 |
| 工单取消 | S＝0 时先撤回任务并处理预建 SN／已打印标签，身份和历史保留；S＞0 时转生产终止／短结处置，按第6.4节核清，不能删除在制或已完工事实 |
| 计划数量调整 | 目标 P 与投产额度 A 分别核对；P 变更检查来源授权、已合格和未决件的处理，A 不得低于 S＋R。批准报废补投后 S 可大于 P；来源数量下降不能直接覆盖本地 |
| NG／返修 | 锁定对应 SN，质量人员授权目标工序／工位及必需复测；不修改普通路线来伪装正常生产。返修站可与原派工不同，但必须有独立合法授权与历史 |

质量问题是否扩大暂停整张工单或整条线，由质量／生产负责人按原因明确决定，不能把单件 NG 自动等同于全线停产，也不能假定只影响当前件。

## 8. 人工、半自动和已有产线 MES 怎么进入同一流程

| 模式 | 派工如何到达 | 实际执行与结果 |
| --- | --- | --- |
| 人工工位 | 下达到本系统的对应工位任务队列 | 人员登录，扫码、装配、录入明确的人工检查，按规则完工 |
| 半自动工位 | 同样下达到本系统工位任务队列 | 人员负责上下料／识别等适用步骤；设备结果关联正确的任务、SN、工序及运行，不能凭浏览器当前 SN 猜归属 |
| 已有产线 MES 主责工序 | 派工发送给明确的产线 MES，携带工单、版本映射和任务修订，分别保存发送、确认和拒绝状态 | 由该 MES 执行约定工序，本系统接收受控事实与证据，不再让人工端重复过站、绑定和报产 |

同一主产线可以混用三种模式，但每道工序的有效执行主责必须唯一。设备加工和安全联锁仍由设备系统负责。

下发成功不是产品完工；业务拒收必须显示原因。相同下达／回传的重试不生成第二份任务或第二份产量。延迟消息按其原任务和责任修订关联，不能套用当前页面、最新派工或新版本。中途接管先核对在制和未决消息，不允许两套系统同时操作同一事实。

发送成功或技术收件不等于业务接受。外部 MES 尚未确认任务及版本映射、或已经拒收时，不得把任务标为已接收或允许正式开工；处理差异后受控重发。先到的执行消息保留原始收件并等待关联／核对，不能据此伪造任务已确认。

## 11. 接下来需要确认的业务选择

已经明确的一单一主产线、派到工位而非个人、自产品默认系统发 SN、目标合格产出与报废补投另批，不再重复询问；现场换单模式未定，本版已按用户要求把两类完整说明，不将任一当作默认确认。工艺联动、派工层级和任务切换见第2.1、4.4、5.2及5.8节；SN与数量／结案见第5.4和第6节，以下只保留需要现场落实的差异：

| 事项 | 本稿建议 | 需要现场确认的内容 |
| --- | --- | --- |
| 正常工位安排 | 每道工序派定一个主产线内工位 | 是否有必需的共享检测、线外资源或同工序多工位分流；有则需补充规则 |
| 产线换单范围 | 整线统一换单、按工位换单两类规则均已明确，现场尚未选定 | 每条线的配方／输送／缓冲／物料隔离及共用资源是否支持独立换单；投用前逐线核定 |
| 接收与开工 | 人工首次开始作业合并记录接收，不加一轮纯确认 | 班组是否必须在实际生产前单独确认接收任务 |
| 编码与标签落地 | 派工后按需系统发号并建档，打印／贴标复核后首站投产；重印同号 | 具体编码格式、标签内容／模板、打印位置及执行岗位；后续外部主码例外的适用范围 |
| 批准岗位 | 生产申请，质量确认判废，计划／生产授权岗位批准补投与结案 | 实际角色和授权范围，短结／超产／目标变更由谁批准；不重新讨论计划数量语义 |
| 必需外部回执 | 数量、质量、版本和必需交接无未知或冲突时才结案 | 当前客户接哪些 ERP／MES／仓储接口，哪些业务回执必须在结案前确认 |

这些选择不影响前述工单—派工—任务—SN执行关系成立，但会影响实际状态和控制条件。确认后再形成实施范围和验收清单，不把建议直接写成现成系统能力。

## 12. 用于核对规则的业务场景

以下是待实施后验证的场景，**不是已执行或已通过的测试**。

| 场景 | 应有结果 |
| --- | --- |
| 同一来源工单重复同步 | 识别原工单，不新增；有差异时显示待处理内容 |
| 工单没有主产线或某工序没有合法实际工位 | 可保留待派工，不能下达或开工 |
| 派 A 线的装配任务，人员在 B 线扫描同一 SN | 即使 B 工位有工艺能力，也因未获本次派工而拒绝正常开工 |
| A01装配、A02检测、A03终检 | 三站各自看到任务，同一 SN 按顺序流转 |
| 第一件装配完成，其他件仍在装配 | 第一件可以到检测，其他件继续前站，不要求整单齐进齐出 |
| 检测工位提前扫描未装配完成的 SN | 显示前序未完成，不产生进站事实 |
| 另一个有权限人员接班 | 恢复原任务、原 SN、原已提交证据，新增动作记接班人 |
| 工位扫描另一工单的 SN | 提示不符，不静默换单；按换单规则处理 |
| 相同动作或设备消息重试 | 原结果可核实，不重复绑定、计产或新建加工 |
| 10台、3道工序全部完成 | 制造产出为10台，工序完成累计不能被当成30台产量 |
| 未执行任务改派、已执行任务改派 | 前者撤回重发；后者核对在制并留修订，既有证据和实际工位不变 |
| 单件 NG、报废补产、计划减量 | 分别进入质量处置、受控补投、数量变更，不删除历史凑数量 |
| 外部 MES 主责工序回传结果 | 正确关联原任务和版本，人工端不再次执行同一过站／报产 |
| 只完成末工序或只收到外部完工通知 | 分别检查制造与质量／结案条件，不自动视为可交付或已结案 |
| 派工后批量发号重试、打印失败重试 | 查询原请求并沿用原 SN；只产生一份有效预留，未投产不计产量 |
| 初始10个未投产 SN 中作废2个再另发2个 | 历史共12个号，有效预留仍为10，投产额度仍为10；旧号码不可复用 |
| 首站扫描任意未知码 | 不静默创建生产单件；先按受控发号／来源核对流程处理 |
| 目标10台，报废2台，批准补投2台 | P＝10、A＝12；最终可为S＝12、G＝10、D＝2，不因S大于P误判超投 |
| 同一个报废件重复申请／批准补投 | 最多一个有效名额；重复处理不重复增加A或生成额外任务 |
| 补投 SN 尚未投产作废、补投件投产后再次报废 | 前者在原名额内另发号；后者凭新的报废件另行申请，不复用已消耗名额 |
| 更换一只报废电芯，父 PACK 继续返修 | 父件沿用原SN，不增加一台PACK补投名额；子件去向、来源工单和原证据可追溯 |
| 已制造完工但尚有待放行、锁定或未决返修件 | 计入U，不能结案；未使用标签也须处理使R＝0 |
| 目标10台，最终8台放行、2台报废，决定不再补产 | 批准短结后保留P＝10、G＝8、不足2及原因；不改成目标8伪装足额 |
| 尚未投产就取消、全部投产后零合格终止 | 前者处理预留和标签后取消；后者按批准终止／零产出短结，保留实际投产及损失 |
| 已结案后售后返修、替换制造或晚到消息 | 原SN开独立返修，新制造用关联新工单；消息核对／更正，不自动重开或改写原结案 |
| 产品路线三节点，所选线只能覆盖其中两节点 | 阻止下达并说明缺项，不临时借别线工位、不默认跳过节点 |
| 同一产线／工位已有A，再下达合法B | B可进入待做队列，不因A忙碌认定工艺不支持；B能否启用另按换单范围检查 |
| 整线模式A仍有有效线内加工，某站想启用B | 拒绝单站换到B，等待整线受控换单；A未结案本身不是唯一阻断条件 |
| 按工位模式A尾件在A03、B首件在A01 | 独立准备、身份隔离和资源条件满足时允许；两张工单各自记录数量与版本 |
| 不同工位共用同一配方、设备或治具 | 按实际共享范围拒绝冲突，不因工位不同默认可并发 |
| 同工单节点10和30都派A01 | 两个工序任务分别校验，切节点不按“重复同单”忽略；同件仍满足路线前序 |
| 只预览B、切页面或新开浏览器 | 不改变服务器当前A，也不释放任何实际资源 |
| 暂停A后直接启用B | 暂停不释放整线／工位上下文，必须先完成受控切换及现场核对 |
| A切到B后仍有A尾件、补投件或返修件回来 | A剩余任务仍可恢复，先排队并受控换回，不自动串入B或永久丢失任务入口 |
| 终端1已从A切到B，终端2用旧A上下文提交 | 拒绝过期上下文或要求刷新，不让各浏览器各有一份有效当前任务 |
| 质量授权A回正在加工B的工位返修 | 授权路径与资源可用分别检查，不越过整线模式或抢占资源 |
