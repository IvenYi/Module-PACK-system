# 基于现有医疗套件的 Pack 改造方案 v0.1

日期：2026-10-23。状态：**用户已确认改造方案并授权分批实施。首条业务为电芯→模组→PACK完整链路，包含 NG 阻断、返修复测、质量放行和双向追溯；所有页面沿用当前样式。**

首批实施及实际验证结果见 [Pack首条制造链实施与验收记录](pack-first-chain-implementation.md)。方案功能矩阵仍表示总体目标，不把首批实现等同于全部功能完成。2026-10-24 工程与规划已统一至 `Module-PACK-system` 单仓库；下文现状与差异描述保留制定方案时的基线，不能视为实施后能力审计。

2026-10-24 的工单、派工和人员执行业务细化见 [业务讨论稿 v0.3](pack-work-order-dispatch-and-execution-rules-2026-10-24.md)：已选择一单一主产线、派工到工位而非个人、自产 SN 默认系统生成，以及合格目标数量与报废补投另批；已补充产品工艺与产线／工位联动、派工层级、任务接收／切换，以及整线和按工位两类换单规则，现场模式尚未选定。各项控制细则仍为业务建议，尚未据此实施。

## 1. 本轮结论与约束

以基于医疗套件复制并适配的 Pack 工程为开发基线，现已与规划统一到 `Module-PACK-system`。继续使用现有工程、应用框架、管理界面、权限体系和基础主数据，生产管理与工作台在原页面上适配 Pack。方案制定时缺少的装配、质量、返修等能力按批补齐，已有实施范围见首链记录。

本方案遵循的已确认方向：

1. 保留现有完整管理界面与作业工作台，包括列表、筛选、分页、详情、维护、导入、版本、审计及相关交互；不另建简化验证台。
2. 沿用用户、角色、组织、菜单、字典、物料、产品、工序、路线、文档、车间和设备的现有实现；对 Pack 必需的字段、范围和业务规则作增量扩展。
3. 保留内置管理员 `admin`，新库初始密码 `admin123`；业务审批使用登录身份、角色、意见和审计。
4. 延续既有 Pack 规划的标准功能页面与工序内标准动作方向；通用表单、独立作业模板中心、DHR 专属业务、电子签名与身份证认证退出最终 Pack 运行链路。
5. 单客户私有化、多租户、多工厂、多车间、多产线，以及人工、半自动、已有产线 MES 协同三模式及混用，仍为产品必选能力；本轮不重新讨论是否支持。
6. 改造在 `Module-PACK-system` 单仓库内实施，规划、源码及启动脚本统一维护；保留旧实现资料的历史边界，不改动医疗源项目和其他项目。保持前端 `3010`、后端 `8090`、数据库 `55440 / pack_edhr_dev` 的隔离配置。

“删除”表示未来从 Pack 菜单、运行依赖、接口及最终代码中退出，不表示本轮已经删除。医疗专属功能虽然有些位于现有“数据”菜单，仍需按业务用途判断，不能因此把表单/批记录模板重新列为 Pack 基础主数据。

### 3.1 权限与主数据沿用时必须补的内容

- 当前路由守卫主要检查浏览器 token；部分角色“数据权限”保存在 `localStorage`，不能作为真实工厂/租户隔离。继续用现有页面与身份模型，把范围保存、查询过滤、命令校验、文件/后台任务授权补到服务器。
- 物料、设备等接口已有动作授权，但用户、角色、工厂、字典、文档等管理接口尚未统一校验管理读写权限。保留已有 RBAC 关系表和维护页，补全后台授权及防越权授予；人员、设备、外部系统账号分别受控。
- 当前 JWT 直接携带权限，不能把“退出成功”或“修改了角色页面”认定为旧权限已立即失效。建议沿用 JWT，增加服务端授权版本/账号状态校验及可撤销会话能力；不因此另写登录系统。
- 当前存在 `Long 1L` 与字符串 `default` 等范围约定，以及多个全表查询；先统一租户/生产范围上下文，再让 Pack 业务进入真实范围控制。
- 物料、产品、路线及文档已有版本能力应继续用；现有生效/失效时间窗之外，补制造版本的校验、发布、冻结和引用保护，发布新版本不覆盖在制品与历史。
- 组织、设备和主数据可以沿用已有实现，但当前有效菜单不能证明已具备完整的工厂→车间→产线→工位维护。现车间迁移还移除了 `site_id`；需明确恢复工厂归属并补工位，而非仅为旧表增加菜单。新增缺失页面，复用现有表格、详情与维护交互。
- 当前 `admin` 是种子账号并关联 `ADMIN` 角色，已有按用户名/角色编码的删除保护；更新接口仍能改用户名、状态及角色。建议在原账号实现上补稳定的内置身份和防误停/剥离管理权限约束。旧 Pack 历史文档中的受保护 `SYSTEM_ADMIN`、自动管理全部工厂等行为并未随本次复制而存在，其管理范围与质量放行职责需明确确认。

## 4. 建议删除的医疗专属能力

以下去留与既有 Pack 蓝图一致，本次仍需随整体改造方案确认后执行。

| 原功能 | 最终处理 | Pack 中保留的业务结果或替代方式 |
| --- | --- | --- |
| 通用表单模板、字段/画布设计器、模型与单元格配置 | 删除 Pack 运行入口和专属引擎 | 人工检验、装配、测试等标准页面；检查项只能配置已支持的类型与判定规则 |
| 表单流程、表单填报/审批/份数、表单待办 | 删除专属链路 | 标准动作运行、结构化记录及业务待办 |
| 批记录模板和 DHR 目录建模 | 删除 | 制造版本直接引用 BOM、路线、动作、规范、位置映射和 SOP |
| DHR 列表、填报、补录、汇总、审批和归档流程 | 删除专属业务 | 单件履历、交付快照与业务质量审批，不强制每个对象创建 DHR |
| 独立作业模板中心及 FORM 等作业节点 | 删除独立配置中心 | 动作直接配置在工序内，形成“路线→工序→标准动作”，操作者不再先建多套模板 |
| 电子签名、签名板、签名密码、签名记录 | 删除 | 登录人、角色、时间、理由、证据和审批结果仍完整保留 |
| 强制签名认证、身份证附件/OCR、签名周期等设置 | 删除相关分支、权限和部署依赖 | 登录、账号、密码及会话策略保留；本轮已安装的 OCR 环境暂不清理 |
| 表单追溯项、表单投影配置/任务、DHR 追溯 | 删除专属实现 | 从装配、测量、物料、质量记录查询和索引；不先伪装成表单再生成业务事实 |
| 基于表单投影的报工/报废/消耗报表数据来源 | 替换后退出旧来源 | 对应业务能力必须保留，改接实际完工、报废和库存事务 |
| DHR 打印专用前端 bundle 与渲染服务 | MES 履历导出替代后删除专属链路 | 通用文件预览、PDF/Excel 工具按实际用途保留；打印/标签仍是 Pack 需求 |

删除必须贯穿菜单、路由、API、权限种子、后台任务、外键/引用保护、设置和构建依赖。只隐藏菜单会留下必填 DHR、自动创建 DHR、投影统计及登录签名等依赖，不能作为完成。

普通业务输入表单、`FormDialog`、输入校验库、审计记录、物料批次、业务审批和 PDF 预览均不属于上述通用表单/DHR删除范围。

| 测试有效性与成品放行 | 表单完成或 DHR 正式化不等于质量合格；换件后测试影响未建模 | 质量详情展示原始/当前有效结果、未完成复测及放行条件 | 装配/软件变更触发受影响测试复核；制造完工、质量放行、包装/入库状态分开 |

当前副本没有独立质量管理路由，不能套用不同提交中的 `QualityReasonPage` 存在性判断。缺陷/报废原因优先扩展已有业务字典与维护方式；如需专门目录，增加 Pack 页面和真实业务引用保护。

## 6. 作业方式与页面组织

### 6.1 一条完整业务链

`主数据准备 → 制造版本校验发布 → 工单/派工 → 工位接单 → 物料与首件准备 → SN进站 → 标准动作执行 → 出站判定 → 下一工序 → 制造完工 → 质量放行 → 包装交接 → 履历追溯`

发生 NG：`登记/锁定 → 质量处置 → 返修授权 → 拆换或受控返工 → 规定复测 → 复核/放行`。

这些业务记录需要明确关联：

- 主数据及制造配置：产品/物料、制造 BOM、路线节点、动作及规范版本、位置/电气映射、SOP。
- 执行：工单快照、生产范围、主责修订、追溯对象、工位访问、动作运行、设备/人工测试运行及原始证据。
- 结果：装配关系及修订、物料流水、质量锁定/处置、返修与复测、放行和交付快照。

`BATCH/SN` 与 `CELL/MODULE/PACK` 分别表达执行粒度和业务类型；物料批次、供应商批次、工单和质量状态也分别管理，不把它们合并成一个状态或同一个编码。

首条建议验收链为“电芯装配成模组 → 模组装入 PACK → 测试 NG → 阻断 → 拆换/复测 → 放行 → 双向追溯”。同时覆盖外购模组来源；缺少供应商电芯明细时明确追溯深度，不生成虚假子件。具体首条现场线和型号仍待第 9 节确认。

### 6.2 管理端与工作台

沿用现有侧栏、多页签和管理页面规范，以菜单配置调整业务分组，建议目标入口如下。尚未交付的业务不提前挂空壳页面。

| 模块 | 入口 |
| --- | --- |
| 首页 | 原首页工作台、业务待办、真实生产/质量概况、操作指南 |
| 数据 | 原物料/产品/产品簇/工序/路线/文档/设备；增量补工厂产线工位、BOM、规范、制造版本及编码配置 |
| 生产 | 原工单、批次/单件、生产工作台；补派工、任务与在制查询 |
| 物料 | 接收、上退料、线边余额、消耗与去向 |
| 质量 | 检验、首件、不良处置、返工返修、复测、成品放行 |
| 追溯（替换医疗“记录”分组） | 单件履历、装配正反查、影响范围、过程/报工/报废/消耗记录、交付报告 |
| 集成 | 设备/外部系统映射、同步状态、冲突、回执、重试与对账 |
| 系统 | 原组织、用户、角色、菜单、字典、图标、设置、登录/审计日志；去除签名和表单专属项 |

工作台保留扫码、当前对象/工单、路线抽屉、SOP/历史/详情侧栏及焦点管理。中心区按当前工序动作显示装配位置、测量点位/设备结果、人工检查、物料或返修操作；服务端返回可执行动作、缺项和拒绝原因。配置标准动作不等于开放任意字段画布或通用脚本引擎。
