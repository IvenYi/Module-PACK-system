# 厂级模组 / PACK MES 产品目标与阶段路线 v1.0

日期：2026-10-23｜状态：产品规划基线，供业务与研发评审；已启动R1-01首条切片实现，现场工艺和接口尚未验收。

现有资料足以确定产品定位、业务蓝图、功能范围及交付顺序。本版以用户已明确的必选目标U1为边界，结合S1/S2历史协议与工艺、S4厂级MES设计、S5采集表、S6架构/路线资料及S7原型的已核实内容形成规划；来源读取深度和限制见[材料评估](../research/materials-and-reuse-assessment.md)与[原型核查](../research/prototype-business-review.md)。来源中的示例数值、冲突及未冻结路线不转为产品常量；未取得的飞书正文不作为规划前置依赖。

本规划不重开“是否支持多租户、多工厂、人工站和半自动线”的范围问题。待确认的是实际项目的参数、接口、实施和验收指标，按影响阶段落实；它们不阻止形成产品级规划，但会阻止对应真实工序或接口上线。

## 1. 产品定位与交付边界

面向电池模组与PACK制造的厂级MES：在单客户私有化部署内提供多租户、多工厂、多车间、多产线管理，统一制造版本、工单协同、现场执行、质量、物料、装配谱系和运营视图。

同时提供无产线MES人工站、无产线MES半自动线、已有产线MES协同三类运行能力，可在同厂同线逐工序混用。厂级直接执行或委托产线MES都遵守相同身份、配置、质量和追溯规则，每工序唯一执行主责，绑定、过站、消耗各自明确权威写入方。租户不预设等于客户、法人或工厂。

产品采用标准功能页面、领域配置与项目适配包。通用基础复用与行业内核分开；工序使用已实现的标准动作，不依赖通用表单、DHR或电子签名。设备动作、实时控制和安全联锁继续由设备系统负责。

| 范围层次 | 本产品负责 | 不自动纳入本版承诺 |
|---|---|---|
| 厂级协同 | 工单建立/导入/同步、派工与确认、在制/质量/物料汇总、ERP及产线MES对账 | APS高级自动排产、全部ERP功能 |
| 直接执行 | 人工扫码/检验/报工，半自动设备结果关联、过站防错、装配与返修 | 自研全部PLC/测试仪驱动、取代设备控制和安全 |
| 行业能力 | 电芯→模组→PACK及关键件/位置谱系，按适用工艺记录点胶/焊接/锁附/气密/EOL等 | 把历史产品路线、数量、编码和阈值套用所有型号 |
| 质量与物料 | 原始证据、规则判定、处置/复测/放行，必要线边收上退耗及库存事务 | 完整QMS/WMS/EAM、成本核算、上游电芯制造MES、完整售后系统 |
| 产品化与运维 | 配置/适配包、范围权限、审计、接口恢复、备份恢复和可核对的业务指标 | 无条件离线放行、未经验证的容量/时延或业务收益数字 |

## 2. 产品目标与可验证结果

目标编号G01–G08用于评审产品结果；功能ID沿用[75项功能矩阵](function-matrix.md)，验收ID沿用[AC01–AC42](../development/contracts-and-acceptance.md#6-开发验收清单)。验收是未来完成条件，不是当前测试结果。

| 目标 | 预期业务结果 | 对应能力 | 可验证结果与证据 |
|---|---|---|---|
| G01 范围与权限 | 一个私有化实例可管理多个租户及多级生产组织，按职责共享和汇总 | M01；M12-05 | 相同显示编码不串租户/工厂；API、消息、任务、附件、导出均受范围控制；AC04、AC22–23 |
| G02 三模式混合制造 | 没有产线MES也可完成生产，有MES的工序可以协同交接 | M03；M04；M09；M10-04/05/06 | 人工、半自动、外部MES在同链路交接；每工序主责和业务写入方可查，重传/接管不双记账；AC24、AC26–27、AC33–34 |
| G03 统一制造基线 | 产品、BOM、路线、动作、规范、SOP与工单分配可追溯，变更不覆盖在制 | M02；M03-05 | 无表单/DHR/电子签名强依赖，生产引用冻结制造/工单快照，同码不同路线不串用；第二配置不用复制引擎；AC01–03、AC19、AC25、AC28、AC35 |
| G04 真实装配谱系 | 能解释电芯、模组、PACK和关键件/位置的当前、历史及交付关系 | M05；M08-02；M11 | 同件唯一有效占用、禁止成环；换芯/换模组前后可还原，外购件显示追溯缺口；AC05–06、AC14–15、AC18、AC29、AC38 |
| G05 质量闭环 | 失败可见、责任可查，返工及复测不能抹掉原始NG或绕过放行条件 | M04；M07；M08 | 原始/规则/复测/最终放行分层，多NG和受影响测试受控，批量返工逐件反馈；AC07–12、AC15–16、AC31、AC36、AC39 |
| G06 物料账实关联 | 收料、上料、退料、消耗、余料转单、替换和回收有明确来源/去向 | M06；M08-02 | 重传不扣二次料，真实返工新增消耗单独记账；标签和产品身份分离，原消耗历史不被切单改写；AC05、AC30、AC37–38、AC42 |
| G07 业务集成可靠 | 工单/版本、设备结果、ERP报工和外部凭证可以重试、定位和对账 | M09；M10 | 收件与业务成功回执分开，重复/冲突/晚到/断网均有可解释处理；AC13–14、AC21、AC26–27、AC33–34、AC40 |
| G08 可运营的标准产品 | 厂级能看清产出、质量、WIP与同步异常，跨型号/路线复用并可恢复运维 | M11；M12；全部模块的配置/适配边界 | 产品数与尝试/复测/返工分别计量，指标可下钻；第二配置/真实型号可复用，数据库/文件/消息恢复可对账；AC17–21、AC41 |

G01、G02等必选目标不是“增强功能”。P0/P1/P2决定优先级和适用范围，R0–R4决定交付与验证顺序，两者不等价。P1功能若为试点工艺或合同必需，必须在该场景上线前完成，不能机械推到R4。

## 3. 业务蓝图与产品组成

[业务蓝图](blueprint.md)定义职责、业务流和对象关系；[功能矩阵](function-matrix.md)定义每项能力的来源、边界、交付阶段与最小验收；[行业设计](pack-domain-design.md)定义标准动作及18组行业能力；[开发契约](../development/contracts-and-acceptance.md)定义建议对象/接口和验收。四者共同支撑本路线，原型的37个业务组不直接等于产品菜单或开发任务。

通用业务链：制造版本发布 → 工单/派工与接收确认 → 生产准备 → 进站及身份/投料校验 → 人工/设备/产线MES执行 → 质量判定 → 正常转序或隔离/返修/复测 → 完工与质量放行 → 包装交接与履历。

跨全链的基础约束为范围权限、版本快照、唯一事实、原始证据、质量锁定和恢复对账。管理端与工位端围绕上述对象提供标准页面；协议字段差异留在适配层，数量、位置、顺序、限值、资源组等留在受控配置。

## 4. 阶段路线与退出条件

阶段依赖：`R0规划基线 → R1核心闭环 → R2现场试点 → R3标准产品发布 → R4增强迭代`。配置、适配和验证可以并行准备，但阶段退出须有对应证据，不能把资料阅读、页面存在或模拟器成功当作真实现场通过。

| 阶段 | 产品成果与交付物 | 主要范围 | 退出条件 |
|---|---|---|---|
| R0 产品规划基线 | 可评审的蓝图、目标、75项矩阵及阶段/来源映射、核心对象和三模式主责契约、演示样例与验收清单 | 本文、蓝图、矩阵、行业设计、接口/验收契约及来源索引；定义工艺/接口缺口的落实阶段 | 每项功能有阶段/边界，必选目标无遗漏，角色与业务链可解释；样例可串起对象/工单/节点/质量/物料，来源冲突有处理原则。退出不要求原件齐备或真实设备已接入 |
| R1 核心闭环 | 可运行的核心验证版、人工工作台、半自动/外部MES模拟适配、最小模组+PACK演示配置及另一套小型配置 | 多组织/租户隔离、身份与权限、制造/工单快照、工位与动作、装配、基本物料、不良/返修/复测、履历和必要指标；事务、消息与恢复基础 | 不需要产线MES即可完成受控人工链路；三模式在同一内核和责任契约下交接；同件并发绑定、重复/冲突报文、NG拦截、换件和追溯成立；第二演示配置通过AC19，多租户/多厂测试通过AC22–27；无表单/DHR/签名强依赖 |
| R2 现场试点 | 试点产品/路线配置、实际设备和系统适配、现场操作流程、联调/UAT及上线运维证据 | 试点适用工艺全部必需记录/判定，首件/换型/余料/标签打印，真实设备/产线MES/ERP等已选接口，质量处置及恢复对账；按确认指标验证节拍/容量 | 所选现场范围的全部P0和工艺/合同必需P1通过；所选现场模式的真实代表性场景、报文/握手及逐笔对账有证据。三模式共同内核在R1模拟验证，未接入模式不声称真实验收；投产前完成数据库/文件/未处理消息一致恢复、权限/质量拦截和操作验收，模拟不能替代真实接口 |
| R3 标准产品发布 | 标准发布包、配置包与接口适配包、部署/升级/回滚/备份操作说明、运维监控与验收报告 | 第二真实型号/不同路线、多线及多厂范围验证；功能和指标口径、权限范围、配置/适配版本、支持边界与已知限制 | 不复制业务引擎即可更换数量/位置/路线/测试/资源；多厂授权汇总和三模式交接仍正确，全部产品P0及本次发行选定P1通过；所声明设备/系统适配已验证，恢复与发布流程可复演；材料样例不成为硬编码 |
| R4 增强迭代 | 有明确范围、数据基础及单独验收的增强包 | OEE/停机分析、SPC、配组优化、设备维保协同、更多报表或复杂跨厂调拨；按实际价值排序 | 数据源、计算口径、责任角色和验收样例明确；不得以增强名义补缺此前上线必需的权限、质量、追溯、物料或恢复能力；完整APS/WMS/EAM等仍须单独立项 |

R1是最小业务切片，不是把所有P0一次开发完；R2上线前补齐试点适用P0和工艺必选，R3完成标准产品全范围验证。多租户/多厂及三模式的模型、权限和基本验证从R1开始，R3仅扩大实证覆盖。备份恢复及监控从R1建立并逐阶段验证，现场上线前必须真实演练，不能整体延后。

R2可以逐工位/产线安排试点，但范围及未验收能力须显式记录。某现场只有人工模式，不妨碍该已验收范围试用；也不证明半自动或已有MES真实适配已验收，更不能取消两者的产品目标。R3发布必须明确覆盖的三模式及已验证适配清单，不承诺全部厂商协议。

## 5. 首个核心切片的业务范围

| 切片 | 最小交付 | 必须保留的约束 |
|---|---|---|
| C1 范围与配置 | 租户/工厂/车间/产线/工位、人员/设备/系统身份；产品/路线/动作/规范与工单快照 | 范围隔离与来源授权；版本变更不改旧在制；工序码包含路线上下文 |
| C2 人工与混合执行 | 人工接单、扫码、装配、检验、报工；半自动及外部MES模拟器 | 无设备人工动作不伪造设备OK；执行主责与绑定/过站/扣料写入方唯一；同事实幂等 |
| C3 装配、质量与物料 | 电芯装模组、模组入PACK，缺陷锁定、拆换、复测、实际消耗与退料处置 | 唯一装配、原始NG/历史关系保留；质量和库存状态分开；无新增消耗复测不扣料 |
| C4 完工、交付与运营 | SN产出、放行、履历/出厂快照、基本WIP和接口队列；故障恢复 | 完工/放行/入库独立；产品数不因复测增加；恢复不丢/不重复业务效果 |

首个演示同时包含模组与PACK不同工单、跨层级合法投料及人工/设备/外部MES来源，并使用清楚标识的演示阈值和条码。另用不同装配N/路线的小配置证明配置化，不能只用一套硬编码跑通后再安排“产品化改造”。完整操作场景见[蓝图第9节](blueprint.md#9-首个验证切片的验收脚本)。

## 6. 依赖、实施决策与落实时点

| 决策/输入 | 规划采用的原则 | 最晚落实时点及未落实的影响 |
|---|---|---|
| 租户业务含义、组织归属、隔离技术与共享授权 | 多租户多厂支持已确定；租户不等于客户或工厂，共享显式授权 | R1真实模型和权限落地前；R0可用明确演示映射说明，不因未选技术推迟隔离设计 |
| 首批产品/工位、真实BOM/路线、数量拓扑/限值、复测与首件规则 | 模组与PACK产品能力均规划，配置按版本发布；样例数值不能当生产参数 | R1用标明的演示配置；R2对应工序生产配置发布前必须确认，否则不得真实自动放行 |
| 设备/产线MES/ERP主责、消息样本、ACK与版本映射 | 每工序唯一执行主责，分别声明业务写入方；适配不绕过内核 | R1冻结模拟契约；R2真实联调前核定实际协议，无法获取则对应接口不进入真实验收 |
| 物料扣料、余料、标签拆并、回收及外部库存职责 | 按真实事务记账；重传不消费，回收不自动合格，历史不改写 | R1基本事务模型及演示规则明确；R2按试点实际流程闭环，所选原型增强也在上线前确认 |
| 离线授权、缓存容量、恢复目标及证据保存 | 缓存不等于离线许可；冲突隔离并对账，恢复覆盖数据库/附件/消息 | R1设计和核心故障验证；R2投产前按现场确认目标实演；不编造RPO/RTO或保存期 |
| 并发/节拍、数据量与曲线图片规模 | 模型先保证一致性，按真实负载验证，不承诺无依据数字 | R2现场验收前明确指标与数据集；结果决定容量、索引、存储及部署调整 |
| 团队/预算/设备联调窗口及合同范围 | 当前只确定顺序、依赖和退出结果，不虚构固定工期或报价 | R0评审后据工作量和可用资源排期；不把材料不足作为不做产品规划的理由 |

需求和业务规则由产品/工艺/质量角色核定，主责与接口由双方系统/设备责任人确认；研发负责实现和验证，运维负责部署恢复与运行证据。该角色分工是规划建议，不指定未经确认的个人。
