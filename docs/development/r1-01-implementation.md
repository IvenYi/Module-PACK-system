# R1-01 实现契约与复现说明

日期：2026-10-23｜范围：[R1-01 目标卡](r1-01-core-loop.md)的首条业务切片。本文描述当前代码及演示夹具，验证状态见第6节；不是全部R1或AC01–42通过声明。

## 1. 工程与可信上下文

后端为Java 21、Spring Boot 3.3.0、JdbcTemplate、Liquibase和PostgreSQL的模块化单体；H2只用于自动化测试。前端为React 18.3.1、TypeScript 5.7.3、Vite 5.4.21和MUI 5.18.0。版本按本轮可用的工程基线固定，不代表依赖升级、安全审计或生产部署认证已经完成。

完整启动、全部配置、数据库创建、旧临时库恢复及排错见[启动与配置手册](local-startup.md)，简要构建入口见[后端说明](../../backend/README.md)和[前端说明](../../frontend/README.md)。默认后端只监听本机；演示初始化须显式启用`MES_DEMO_ENABLED=true`并通过`MES_DEMO_PASSWORD`设置至少12字符的本地演示密码。根目录提供`.env.example`，复制填写后的`.env`须显式导出到后端进程环境，不会自动读取。密码不写入仓库；重启不会清空业务数据或覆盖已有账号密码。

身份来自登录后的Bearer令牌，服务端保存令牌摘要并重新加载当前账号及工厂授权，退出登录使当前会话失效。租户、角色和人员/设备/外部系统来源不从业务请求的任意字段取得。前端令牌及待确认请求保存在当前页面内存中；页面刷新或关闭后的客户端待发请求恢复尚未实现，不能据此承诺持久化的边缘离线队列。

| 演示账号 | 身份/范围 | 本切片动作 |
|---|---|---|
| `engineer` | T1 / T1-F1，HUMAN、ENGINEER | 建立/发布制造版本、工单及对象，收料 |
| `operator` | T1 / T1-F1，HUMAN、OPERATOR | 创建对象、收料、人工进站/绑定/检验/出站、打开测试访问、执行已授权换芯 |
| `quality` | T1 / T1-F1，HUMAN、QUALITY | 授权返修、检查复测后关闭返修、质量放行 |
| `device-sim` | T1 / T1-F1，DEVICE | 仅提交匹配本身份和设备来源工序的模拟测试结果 |
| `mes-sim` | T1 / T1-F1，MES | 仅提交匹配本身份和产线MES来源工序的模拟测试结果 |

## 2. W1 核心对象、唯一键与状态

业务事实使用独立关系记录。配置和报文可保存JSON，但装配、测量、库存事务、质量锁定、返修和放行不只存在页面状态或整对象JSON中。DDL见`backend/src/main/resources/db/changelog/001-foundation.sql`、`002-domain.sql`及`003-dispatch.sql`。

| 对象 | 身份及防重复边界 | 本切片语义 |
|---|---|---|
| 制造版本/位置/规范/节点 | 租户+工厂+版本编码；位置/测项在版本内唯一 | DRAFT→PUBLISHED，发布后冻结摘要；通过新版本改变N及测项 |
| 工单 | 租户+工厂+工单号；独立orderSnapshotId | 冻结制造版本、数量、车间/产线及来源投料分配；访问工位须匹配派工产线 |
| 产品/物料对象 | 租户+工厂+SN | CELL、MODULE、PACK；制造对象数量不能超过工单计划 |
| 工位访问 | 对象+节点的活动访问唯一 | 冻结工单快照、节点、责任修订、装配修订及组织资源；真实复测建立新访问/尝试 |
| 装配关系 | 有效子件归属唯一、有效父件位置唯一 | 每次绑定独立关系；换芯结束旧关系，不删除旧关系 |
| 人工检验证据 | 独立记录，关联访问及装配修订 | 人员来源，不伪造PLC OK；结构变化使原人工检查不再授权当前装配出站 |
| 测试运行/测量 | 租户+工厂+来源类型+设备身份+外部runId | 原判、规则判定、完整性、当前有效性及测项分别保存；复测不覆盖原记录 |
| 物料事务 | 范围内businessKey唯一 | RECEIVE、CONSUME、QUARANTINE分别记录；通信重试和无新增实耗复测不扣料 |
| 返修/质量锁定 | 每对象至多一条活动返修；授权绑定装配修订 | AUTHORIZED→RETEST_PENDING→CLOSED；未齐复测不能关闭；原NG留存 |
| 首次有效产出 | 每对象唯一事实 | 模组和PACK分开计数；测试尝试、复测、返修不增加唯一产品数 |
| 放行/成员/证据 | 对象装配修订关联冻结放行记录 | 与生产完成分开；当时构成和证据可恢复，历史快照不随当前关系变化 |
| 命令回执/冲突/审计 | 租户+工厂+认证来源主体+requestId | 业务效果与成功回执同事务提交；异载荷不覆盖原回执，保留冲突记录 |

命令在已授权工厂行上取得数据库锁，并将业务写入和回执统一提交，作为本切片的并发一致性方案。该锁粒度不是生产吞吐承诺；尚未做现场负载和节拍验证。数据库唯一约束继续保护有效装配关系、运行及物料业务键。

当前支持的路线是人工装配`ASSEMBLY`→测试`TEST`。节点使用稳定ID并属于具体制造版本；显示码不单独作为跨路线身份。模组测试为本产品执行主责、DEVICE来源；PACK测试为LINE_MES执行主责、MES来源；绑定/消耗写入方为PRODUCT，过站写入方随节点主责。MES测试回传不再创建一次装配或消耗。责任迁移和外部真实接口映射还未实现。

配置已经支持位置集合N及测项集合；最小BOM/兼容检查为位置与子件类型，尚不是完整物料型号、替代料、单位及版本生效管理。不能把本切片描述为任意路线设计器或全部行业工艺已经可配置。

## 3. HTTP 与模拟报文契约

| 接口 | 请求/结果 |
|---|---|
| `POST /api/login` | `{username,password}`；返回token、当前user和授权factories |
| `GET /api/me`、`POST /api/logout` | Bearer身份读取与当前会话失效 |
| `GET /api/state?factoryId=...` | 当前授权范围的配置、工单、对象、访问、装配、测试、人工证据、物料、返修、锁定、放行、主责、工位及计数；另附消息和冲突概览 |
| `GET /api/trace/{sn}?factoryId=...` | 对象、当前/历史关系、测试、物料及包含该对象的冻结放行快照 |
| `POST /api/commands/{action}` | `{factoryId,requestId,payload}`；返回APPLIED、DUPLICATE或明确的REJECTED/CONFLICT |
| `GET /api/receipts/{requestId}?factoryId=...` | 查询当前认证发送主体在此范围的原持久化业务回执 |

业务拒绝携带HTTP状态、`code`和`message`。请求ID相同且载荷相同返回原结果；同ID异载荷返回409并隔离。不同请求ID携带相同设备业务运行及相同内容时，测试运行层再次判重；同业务运行异内容拒绝，不能凭换messageId改写原始测试。

| action | payload最小字段 |
|---|---|
| `create-version` / `publish-version` | `{versionId,productType,slots:[...],testItems:[...],testSource}` / `{versionId}` |
| `create-order` | `{orderNo,versionId,quantity,lineId?,allowedSourceOrder?}`，PACK来源单必填；lineId省略时取工厂默认线，显式产线须属同范围 |
| `create-object` / `receive-material` | `{sn,type,orderNo?}` / `{sn}` |
| `open-visit` | `{sn,node,stationId}`；返回可信访问、快照、节点、责任修订及组织资源 |
| `bind` | `{visitId,childSn,slot,targetOrderNo}` |
| `manual-check` / `complete-visit` | `{visitId,result}` / `{visitId}` |
| `test-result` | 下方模拟报文；DEVICE/MES身份限定，设备/通道/访问/节点/快照/责任修订必须匹配 |
| `authorize-rework` / `replace-cell` | `{sn,reason}` / `{reworkId,oldChildSn,newChildSn}` |
| `close-rework` / `release` | `{reworkId}` / `{sn}` |

例如，先以操作员打开M001的TEST访问，再以`device-sim`登录提交：

```json
{
  "factoryId": "T1-F1",
  "requestId": "demo-M001-test-01",
  "payload": {
    "visitId": "使用open-visit返回值",
    "runId": "M001-device-run-01",
    "orderSnapshotId": "使用该访问的orderSnapshotId",
    "nodeId": "使用该访问的nodeId",
    "responsibilityRevision": 1,
    "deviceId": "device-sim",
    "channel": "CH1",
    "rawResult": "NG",
    "results": { "DEMO_CHECK": "NG" }
  }
}
```

责任修订也应取访问返回值；上例1是演示初始修订。DEVICE/MES、CH1、DEMO_CHECK及OK/NG是受控模拟契约，不代表已经直连设备或确认真实电性能阈值。必需测项缺失或非法，不能仅凭原判OK形成有效合格检验。

前端在网络错误/回执不明时显示待确认，保留原不可变请求供重试；业务拒绝不会显示为成功。断连不授予新离线放行。服务端有持久化回执并不等于客户端具备持久化离线队列。

## 4. 主链复现顺序与预期

使用独立演示数据库。初始化只建立组织、账号及草稿制造配置，不预先伪造生产事实。可用前端对应标准页面操作，接口复现按以下顺序；自动化用例位于`backend/src/test/java/com/zencas/mes/ApiFlowTest.java`。

1. 工程账号发布`DEMO-M-V1`（两个CELL位置）及`DEMO-P-V1`（两个MODULE位置）。建立模组单`WO-M`数量2、PACK单`WO-P`数量1，PACK合法来源分配为`WO-M`。
2. 建立C001–C005、M001/M002及P001并绑定相应来源工单：接口允许操作员建档，当前前端须由工程账号在“序列化对象建档”完成。随后操作员收料，为M001打开人工装配访问，在S1/S2绑定C001/C002，完成人工OK检查及出站。当前本机已有演示事实，手动重跑时使用[启动手册第13节](local-startup.md#13-用当前账号手动跑一轮完整业务)的新编码。
3. 为M001打开测试访问。设备模拟账号以新runId提交NG，确认原始NG、规则判定和质量锁定存在；重传同请求和同运行不同请求不增加测试、扣料或产量。尝试无授权放行应被拒绝。
4. 质量账号授权M001单件换芯，保留返修ID。操作员按授权用C005替换C002；C002旧关系结束并进入质量隔离，原NG仍可查询。未复测时关闭返修应被拒绝。
5. 操作员打开M001新测试访问，设备模拟账号以新runId提交完整OK；质量账号检查并关闭返修。M002人工装配C003/C004并完成设备模拟测试OK。
6. 为P001打开人工装配访问，在S1/S2绑定来自WO-M的M001/M002，完成人工检查及出站。打开P001测试访问，由`mes-sim`提交完整OK。质量账号单独执行P001放行。
7. 查询P001、C001、C002的谱系和放行记录。当前电芯为C001/C005/C003/C004；C002有M001历史，但其有效装配区间在M001进入PACK前结束，所以不能成为P001交付成员。
8. 发布`DEMO-M-V2`（三个CELL位置），建立独立新工单和对象完成三位置演示；旧WO-M仍引用V1两个位置及原快照，不复制引擎或覆盖历史。

在执行第二配置前，主链预期模组唯一产出2、PACK唯一产出1、测试运行4（M001初测NG及复测OK、M002及P001各一次），电芯实耗5、拆出电芯隔离1。总消耗表还包含模组投入PACK的装配消耗，不能将其与电芯耗用量混为同一个统计口径。演示复测不增加唯一产出。

业务事实摘要不包含预期新增的登录会话和重放回执。统计`holds=0`指未闭环的制造质量锁定记录；拆出电芯C002仍为HOLD/隔离状态，页面按对象统计的质量锁定数量可为1，两者不是同一口径。

本轮仅监听本机：前端5173、后端8080、临时数据库55432，数据库工作目录为`/tmp/zencas-r1-postgres`。初始化共享内存及后端连接曾被沙箱拒绝，均确认未成功后通过正式权限提升获准重试，现已完成，无未决权限阻碍。临时演示数据不是正式部署；进程重启及回执补传不等于真实设备断网、崩溃容灾或AC21联合备份恢复演练。
