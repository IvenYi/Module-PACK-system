# R1-01 最小模组 → PACK 业务闭环目标卡

日期：2026-10-23｜目标状态：首版核心切片已实现并完成本轮联验｜依据：产品规划基线v1.0｜代码契约、复现与验证边界见[实现说明](r1-01-implementation.md)。

## 1. 目标与完成结果

交付一条**可运行、可重复验证的演示业务链**：制造版本与工单发布 → 人工扫码装配模组 → 模拟测试NG → 质量锁定 → 授权换芯与复测 → 模组装入PACK → 演示检验及质量放行 → 查询当前/历史/交付履历。

这条链从开始就带租户/工厂/车间/产线/工位范围、制造与工单快照、每工序唯一执行主责，以及绑定/过站/扣料权威写入方。人工站不依赖另一套MES或虚拟设备OK，半自动与已有MES采用明确标识的模拟适配，共用同一业务内核。

R1-01完成仅代表首条核心切片通过，不代表整个R1、75项功能或真实产线已验收。阶段范围沿用[产品目标与阶段路线](../product/product-goals-and-roadmap.md)，功能与验收口径沿用[功能矩阵](../product/function-matrix.md)和[开发契约AC01–42](contracts-and-acceptance.md#6-开发验收清单)。

## 2. 本目标范围

| 范围 | 本次最小交付 | 保留的边界 |
|---|---|---|
| 基础工程与范围 | 独立可启动工程/数据库、登录/动作权限、组织与人员/设备/系统身份 | 单客户私有化内多租户多厂；租户不等于客户或工厂；不依赖DHR/通用表单/电子签名 |
| 制造与工单 | 最小产品/BOM/路线/动作/检验规范、模组与PACK分层工单、冻结快照 | 不建完整工艺设计器；发布校验和版本不可静默覆盖 |
| 人工执行 | 固定工位接单、扫码、位置绑定、人工检查与基本报工 | 无设备动作使用人工规则及人员来源，不伪造设备采集 |
| 半自动/MES协同 | 两类受控模拟适配及收件/业务回执状态 | 每工序主责明确；设备/MES模拟不冒充真实接口，不控制设备安全动作 |
| 装配、质量及物料 | 单件/位置关系、基本收上退耗、NG锁定、单件换芯、测试失效/复测 | 不做全套库存模块或复杂审批；事务、原始结果、实际消耗及拆出件去向必须真实记录 |
| 履历、计产与恢复 | 当前/历史/演示放行快照、唯一SN产出、消息对账和基本重启恢复 | 不以截图或页面汇总数代替持久化事实；不承诺真实负载、RPO/RTO或现场恢复验收 |

真实PLC/设备/MES/ERP驱动、全部行业工艺、标签拆并与完整包装、批量返修/复杂多NG、报工凭证、OEE/SPC及正式联合备份恢复演练不纳入此切片。它们保留在后续R1目标或R2/R3；AC21真实部署恢复仍须在R2投产前完成，不能因本目标演示成功而省略。

## 3. 演示夹具与主责

以下编码、数量和检验规则只用于验证，均不代表实际工艺、租户业务含义或产品容量。

| 夹具 | 约定 |
|---|---|
| 范围 | 建立DEMO-T1/DEMO-T2两个租户，每租户两个演示工厂及车间/产线；主链在一个工厂运行，其余范围用于同码解析、授权汇总与越权负例；演示归属不作为正式组织映射 |
| 对象与工单 | C001/C002组成M001，C003/C004组成M002；M001/M002装入P001；C005用于替换C002。模组工单WO-M和PACK工单WO-P分开，并有合法投料分配 |
| 制造/工单基线 | DEMO-V1冻结BOM、节点、位置、动作、检验规则及派工；工序显示码必须带路线/节点映射，不能脱离范围解释 |
| 三种模式 | 模组装配为人工主责；模组测试为本产品主责、模拟设备上报；PACK演示检验由模拟产线MES主责。责任契约逐项指定绑定、过站和消耗写入方；厂级接收外部事实不再次产生业务效果 |
| 检验 | 使用明确标识的DEMO_CHECK规则及OK/NG输入；原始结果、规则结果、复测尝试及最终放行分开。此规则不代表任何真实电性能阈值 |
| 返修与实耗 | M001的C002异常并被C005替换；结束旧关系，原NG保留，相关测试待复核；C002进入演示质量隔离去向，C005的新消耗独立记账；通信重试或无新增实耗复测不再次扣料 |
| 第二配置 | DEMO-V2使用不同装配N、路线或测项组合，另用演示对象运行；不得修改引擎、复制客户页面或覆盖DEMO-V1历史快照 |

模拟报文至少有可信范围/来源、messageId、业务运行键、工单快照、路线节点、访问/动作、设备/通道及责任修订的可核对关联。相同ID异内容冲突隔离，不同ID同运行也须业务判重；不能把当前页面SN自动套到未关联报文。

谱系按实际时点解释：当前C001可正查至M001/P001，C002保留曾装入M001的历史；本例C002在模组入PACK前已换出，不能因此显示为P001交付组成。候选影响追查与某时点实际装配分别标识。

完成主链后，有效装配电芯为C001/C005/C003/C004；模组和PACK首次有效产出分别核对为2件、1件，复测不增加这两个数；替换芯C005的新增实耗单独记账。这些数量仅为本夹具的预期结果。

## 4. 完成标准与证据

下表是本目标采用的AC核心子场景；未覆盖的完整工艺、真实接口和部署范围须单列，不能把整项AC提前标为通过。

| 目标检查 | 必须观察到的结果 | 关联验收及证据 |
|---|---|---|
| D01 范围与权限 | 跨租户/工厂同码正确解析，无权直接API、消息或附件访问被拒；设备身份不能执行人工质量批准 | AC04、AC22–23核心部分；身份/范围配置及允许/拒绝记录 |
| D02 版本与配置 | 不使用DHR/表单/签名即可发布演示配置并开工；V2不覆盖V1在制及历史 | AC01–03、AC25核心部分；发布校验、内容快照及旧记录查询 |
| D03 人工与三模式交接 | 主链完成接单、人工扫码/检查、模拟设备测试及模拟MES工序；每工序主责可查，人工步骤无虚拟设备回执 | AC24–26、AC29核心部分；每次访问/动作和来源事件时间线 |
| D04 装配唯一性 | 并发或重复绑定同一电芯只产生一条有效归属；错位置、缺件和错误目标工单被拒 | AC05、AC29核心部分；成功/拒绝响应、装配与物料事务 |
| D05 NG与返修 | NG不能正常进入后序；授权换芯后相关测试重新待复核，原NG/旧关系保留，复测齐套才可继续；按规则失效的旧OK不能放行 | AC10、AC15–16、AC31核心部分；原始/复测、锁定、返修及批准/解除依据 |
| D06 消息与数量 | ACK丢失重传、同运行换ID、同ID异内容有确定处理；不重复绑定、扣料、计产，真实换芯新增耗料可对账 | AC13、AC17、AC26、AC30核心部分；原事件/消息、冲突记录及前后数量对账 |
| D07 履历与放行 | 当前电芯正查PACK，PACK反查构成；C002仅见M001历史、不成为P001交付组成；替换前后及演示交付快照可还原，生产完成与质量放行分别记录 | AC15、AC18核心部分；对象树、时间线、原始证据引用与放行快照 |
| D08 第二配置 | 不复制引擎即可运行DEMO-V2，原配置仍可查询；修改N/路线/测项不需新建客户专属业务模型 | AC19核心部分；两套配置及运行结果、变更范围说明 |
| D09 基本故障恢复 | 服务重启/回执丢失后能查询原处理结果并继续补传，无授权的离线关口不自动新放行 | AC33核心部分；恢复前后业务状态、队列/消息与逐笔对账；不替代AC21真实演练 |

每份证据至少注明输入、预期、实际、版本、对象/访问/消息ID和未覆盖范围。交付可运行入口及复现步骤、演示配置/数据说明、核验结果和已知限制；截图只作辅助，业务效果以持久化事实及对账为准。

AC27主责迁移、AC28跨路线同码/歧义拒绝等完整负例留后续R1专项验证，仍须遵守本目标先建立的责任修订与路线节点身份模型，不能以本切片未全面取证为由绕过这些约束。
